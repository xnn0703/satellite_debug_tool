# M19-A.11 灵境运动平台直接控制组件验收标准

## A. 组件边界与唯一所有权

- [x] `core/motion_platform/` 不依赖任何 UI 或试产页面模块。
- [x] 试产批次、夹具调试和摇摆台自动测试只调用组件公开接口。
- [x] 同一平台只有一个 socket owner 和一个动作状态源；并发 owner 申请被明确拒绝。
- [x] MS-6222 保持独立组件，上层可以选择组合，运动平台组件可单独复用。
- [x] 厂家服务进程、A6/A6T 转发、发行资源和打包钩子已从活动实现中删除。

## B. 协议与运动学

- [x] `0xC0` 位置帧、`0x03` 回原点帧和 68 字节反馈帧通过 DLL 固定向量及抓包向量测试。
- [x] 已确认姿态的六轴目标与原 DLL 输出一致。
- [x] Roll 32°、逻辑姿态越界及任一执行器越界均整条拒绝，网络发送计数保持不变。
- [x] 逐轴钳位实现、兼容入口和失效测试已删除。
- [x] 未知型号或几何参数哈希不匹配时不允许运动。

## C. 状态与完成语义

- [x] UDP 写入成功只产生“指令已发送”事件。
- [x] 单点动作只在本次连接代际的六轴反馈满足容差、稳定时间、运行态和无故障后完成。
- [x] 旧实现“发送后按预计时长完成”的故障有稳定回归测试，新实现稳定通过。
- [x] 回原点可容纳抓包已证明的长反馈中断，并只在完整状态链和稳定反馈后完成。
- [x] 反馈序号或控制器时间回退使当前动作失败并进入 `RECOVERY_REQUIRED`。
- [x] 普通反馈超时进入 `OFFLINE`；重连后重新确认状态，不沿用旧动作结果。
- [x] 任一伺服错误使当前动作失败并进入 `FAULT`，诊断保留轴号和原始错误码。

## D. 轨迹质量

- [x] 轨迹启动前完成全部采样点的姿态和执行器范围校验。
- [x] 20 ms 调度基于绝对单调时钟，不累计串联 sleep 漂移。
- [x] 调度迟到时不会突发补发历史采样点，并记录迟到和跳点统计。
- [x] 正弦轨迹的位置、速度和加速度连续，结束点通过反馈闭环确认。
- [x] `stop_trajectory()` 的状态和文案只表示受控停止，不声明急停或快速停止。

## E. 档案、UI 与证据

- [x] 型号预置正确生成 `.101:8410` 本机绑定与 `.201:7408` 控制器端点。
- [x] 旧 schema 按稳定型号迁移；旧 `:9800` 地址不会被当成控制器端点。
- [x] UI 实时显示组件状态、反馈年龄、六轴目标/实际/误差和错误码。
- [x] UI 只依据组件动作结果显示“已到位”与“回原点完成”。
- [x] 诊断 ZIP 包含配置、原始帧、解析反馈、状态迁移、动作指标、异常和 manifest。
- [x] 配置、协议、几何参数、关键证据文件均有 SHA-256。

## F. 自动化验证

- [x] 新增协议、运动学、状态机、轨迹、迁移、证据和 UI 语义回归测试。
- [x] `python3 scripts/update_translations.py update` 后翻译资源已提交到工作区。
- [x] `python3 scripts/update_translations.py check` 通过。
- [x] `PYTHONPATH=. pytest satellite_debug_tool/tests` 全量通过，无新增允许失败项。
- [ ] Windows PyInstaller 构建通过，产物中不含厂家服务程序。

## G. 真机分级验收

- [ ] 静止连接后反馈周期、六轴位置、运行态和错误码稳定。
- [ ] 回中及 Roll/Pitch/Yaw 单轴 `±1°` 动作由控制器反馈确认完成。
- [ ] 低幅三轴正弦连续运行，命令调度和 MS-6222 记录无异常突跳。
- [ ] 回原点完成条件与供应商抓包状态链一致。
- [ ] 断网重连后进入恢复流程，旧动作不被误报完成。
- [ ] 物理急停后的控制器重启被识别，人工确认后可显式恢复回中。
- [ ] 软件界面没有硬限位、软件急停、取消定位或快速停止的虚假能力声明。
