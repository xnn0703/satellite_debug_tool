# M48 批次测试布局计划

状态：2026-10-30 用户确认并实施完成；配色、字体沿用客户页面共享样式。软件验收记录见同编号开发记录与验收文档。

## 目标

把“本批次做什么、当前做到哪里、还要多久、设备信号怎样”放在同一视线内。布局自上而下为：精简批次设置 → 横向测试节点与当前阶段/大号剩余时间 → 紧凑夹具指示灯 → 实际参与设备曲线 → 折叠事件与常驻操作。

## 布局与数据合同

1. **曲线按批次设备显示。** 单设备只有一张全宽曲线；2 台并排；3～4 台响应式排列。未参与设备不占空卡片。批次冻结后以真实参与者 ID/endpoint 为准，不能直接显示 slot 1..N 而隐藏处于历史 slot 4 的唯一参与者。保留 endpoint 固定绑定；重排只改变呈现位置。
2. **节点进度居中横排。** 放在批次设置和曲线之间，按冻结配方和实际执行步骤过滤；固件/参数等必需步骤沿用领域合同。未启用的测试不显示节点。派生汇总与独立物理工况保持各自语义，缺少判据的启用项目保留明确状态，不能省略以伪造完成。
3. **当前阶段和计时显著。** 节点上方突出测试名称、阶段、第 n/N 项和大号 `HH:MM:SS` 剩余时间。分别标识“本项已用”和“工况剩余”；时间来自 M47 进度快照，准备、搜星、观察、中止和结果均消费同一领域状态。倒计时到零仍需动作收尾及分析结论。
4. **夹具使用灯与文字。** 电源、摇摆台、MS-6222 等依赖以紧凑横条显示。绿色表示已取得就绪/当前动作的有效证据，文字区分“就绪”和“运行中”；红色表示本工况未就绪，文字保留已配置、连接中或故障等真实状态；灰色表示本批次无关。`CONFIGURED` 不转换成 `READY`。详情放在 tooltip 或可展开区域，始终可以查看端点、回读和故障原因；颜色同时配文字。
5. **配置与事件收敛。** 批次 ID、产品、数量、工位和输出目录仍可查看；创建后按现有规则锁定。配置参数/哈希明细收进详情，避免长串占据主视区。批次事件默认折叠为最新事件摘要，可以展开完整日志。
6. **操作保持可见。** 中止按钮在底部固定操作区，运行、准备、中止中、结束及错误状态沿用 M47 合同。报告操作保留现有准入。
7. **只调整呈现。** UI 从 M47 唯一领域 owner/Store 读取节点、阶段、参与者、夹具相关性和状态，只发意图。此里程碑不修改配方执行顺序、电源/运动控制、租约、SNR 判据或证据收尾。

## 实施与评审顺序

- 用户确认布局效果图与本计划后，建立可复用节点进度/夹具状态呈现控件。
- 将现有工作区映射到冻结参与者和已启用步骤，删除被替代的右侧表格与固定四卡呈现路径。
- 维护同编号开发记录；完成响应式、多语言与三主题检查。
- 对照验收文档检查事实来源、状态流、相邻入口和回归；软件验证与真机测试分别报告。默认源码交付，打包、提交由用户另行要求。
