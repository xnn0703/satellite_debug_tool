# M58 摇摆台连续运动、组合包线与预录制可靠性验收标准

## A. 软件回归

- [x] 注入 200 Hz MS 样本、50 Hz 目标和五分钟可见窗口时，单次绘图输入量受固定像素预算约束；会话运行时间不扩大单次投影工作量。
- [x] 轨迹结果保存实际相邻发送间隔最大值、P95、P99、控制空洞数量和跳点数量；跳点不会覆盖原始空洞。
- [x] 超出命令覆盖窗口的实际发送间隔保存为控制空洞；完整槽位迟到保存单一 timing-fault 事实。M60现场证据确认停止会放大瞬时迟到，现行合同为不跳点继续发送并重建周期。
- [x] 连续轨迹支持的采样周期来自独立资格合同；单次动作 `minimum_duration_ms` 不再直接代表连续轨迹能力。
- [x] 14°现场轨迹预检通过，并报告 axis 4 最小余量约 0.51 mm。
- [x] 同参数 15°轨迹在预览阶段拒绝，并报告 axis 4、限制姿态和 `-0.21 mm`。
- [x] UI 预览与 worker 启动使用同一不可变预检结果；参数变化使旧结果失效。
- [x] 严格逆运动学保持整条拒绝；代码和测试中不存在逐缸钳位或自动缩小角度路径。
- [x] 设备离线时点击预录制立即建立一个 Runtime recorder，并进入 `RECORDING + WAITING_DEVICE`。
- [x] 首个上线 UDP 数据写入同一 SDB，且其时间早于完整采集请求回执。
- [x] 首次完整采集发送失败、超时、拒绝或能力待确认时，recorder 保持活动并保存明确采集阶段。
- [x] 新在线代际基于新身份与能力证据发起一次新协商；同一代际不做定时盲重试。
- [x] 用户停止后同一文件完整收尾；summary 分别报告原始录制完整性和 `support_full` 覆盖区间。
- [x] 相邻入口回归覆盖客户总览、工程共享 UDP、Production recorder freeze 和应用退出，证明 recorder owner 唯一。

## B. 抓包与台架验收

- [ ] 真实 Mac/Windows 工作站分别运行不少于 10 分钟的三轴 14°轨迹，页面保持可见并同时采集 MS-6222、DUT support_full 和外接电源。
- [ ] 50 ms 资格运行中，每一条实际命令到达间隔均小于前一命令携带的完成时间；若合同采用不同完成时间，证据记录两者及安全余量。
- [ ] 抓包中控制器反馈序号连续，反馈周期稳定，六轴伺服错误码为 0；控制器重启或故障形成独立失败。
- [ ] 轨迹报告中的发送间隔、命令数和控制空洞与 pcap 逐包分析一致。
- [ ] MS-6222 的 10°运行三轴峰峰值分别接近 20°；14°运行三轴峰峰值分别接近 28°。允许误差由现场机械验收负责人冻结，软件不自行宣称物理 PASS。
- [ ] 20 ms 连续轨迹只有在独立 10 分钟抓包和 MS-6222 平顺性验收满足同一时间线合同后才标记为支持。
