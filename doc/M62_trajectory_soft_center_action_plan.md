# M62 连续摇摆缓停回正入口修复计划

## 根因

1. 缓停状态机和worker入口已经存在，组件回归也能完成渐出与反馈闭环回正。
2. 唯一按钮装配在“绝对运动”区域，连续摇摆区域没有就地停止入口。
3. 高频平台反馈会调用 `_set_motion_controls_enabled()`，其中无条件禁用缓停按钮；即使轨迹启动信号曾启用按钮，下一帧反馈也会覆盖该事实。

## 修复

1. 同一个缓停按钮移动到连续摇摆区域，与“开始组合摇摆”并列，不增加第二个动作owner。
2. 页面明确保存控制忙碌、活动请求类型和缓停已请求三个肯定状态。
3. 单一按钮投影函数只在“会话可控制 + 当前轨迹运行 + 尚未请求缓停”时启用。
4. 平台反馈刷新、busy信号、request-started信号和缓停阶段信号都消费同一状态，不再直接互相覆盖按钮。
5. 缓停请求发出后按钮保持禁用，直到本次轨迹完成；普通绝对运动期间不可用。

## 验证

- UI回归覆盖 `busy → request_started → 高频状态刷新` 顺序，按钮仍可点击。
- 点击后只调用一次worker缓停入口，按钮保持禁用并显示阶段。
- 轨迹完成后恢复开始按钮，缓停入口回到禁用状态。
- worker渐出、回正闭环及全量测试保持通过。
