# M19-A.13 共享夹具运行时、姿态外环与正式自动化计划

## 1. 目标

在已经完成电源、摇摆台和 MS-6222 真机验证的基础上，建立一个进程级共享夹具运行时，并依次交付：

1. 将已确认坐标标定固化为当前工作站安装资产，支持校验、导入和导出。
2. 同时提供 MS-6222 绝对真航向与摇摆台相对 FRD 姿态，避免两个 Yaw 概念混用。
3. 在客户工作区提供摇摆台连接与姿态控制弹窗。
4. 使用 MS-6222 建立有安全边界的低带宽姿态外环。
5. 将电源、设备、摇摆台和 MS-6222 接入正式批次自动执行器，先打通静态、锁定后摇摆、摇摆中上电三种全自动台架工况，再接入台架动态模拟和人工车辆工况。

## 2. 已确认事实

- 当前工作站档案 `lingjing-a6-200mm-01` revision 6 已引用标定 `MS6222-CAL-20261009T110120297774Z-07A3855205CE-2CEFB694`。
- 新标定三轴中心离散度为 `0.0031° / 0.0023° / 0.0153°`，三轴映射为同轴同向，最大串扰约 `0.92%`。
- MS-6222 原始 Yaw 是约 `153.45°` 的绝对航向；当前联合曲线显示的是以标定中心为零位的相对 FRD Yaw。
- 摇摆台控制器已有执行器位置内环；MS-6222 可以作为独立姿态参考增加外环，不能替代急停、限位和供应商伺服保护。
- 20 ms、80 s 三轴轨迹计划 4000 点，实际发送 3999 点、跳过 1 点；主机调度和约 80 ms 的姿态观测滞后不支持直接以 200 Hz 原始测量逐帧纠偏。
- 当前 `ProductionWorkspace` 自己创建摇摆台与 MS-6222 租约；客户工作区没有共享夹具入口。若客户弹窗另建控制器，会出现两个 owner 和两个状态源。
- 正式批次目前能够完成配置冻结、电源身份/输出闭环、参与设备冻结和证据录制；各工况 attempt 尚未由统一状态机自动执行。

## 3. 标定固化合同

坐标标定作为“物理安装资产”固化，不作为摇摆台型号常量写入源码：

- 摇摆台型号预设只保存控制坐标、几何、通信参数和硬限值。
- 工作站夹具档案引用一个已确认标定 ID；标定保存 revision、SHA-256、创建时间、中心绝对航向、轴映射、符号、零偏、响应矩阵、串扰和稳定性指标。
- 标定增加稳定的参考安装 ID；若 MS-6222 协议不能读取硬件序列号，由工作站配置保存人工确认的设备编号。
- MS-6222 更换、拆装、天线方向变化、平台机械调整或档案几何变化后，旧标定进入 `requires_revalidation`，不能继续产生姿态真值结论。
- 每次连接后在中心位置执行快速一致性检查；相对姿态和绝对航向质量均满足门限后才进入 `ready`。
- 工作站配置导出包含被引用的夹具档案和标定；导入先校验全部 revision、引用和 SHA-256，再原子提交。

当前已保存的标定继续保留；迁移后补充安装身份与快速复核记录，不重新把数值手写进型号预设。

## 4. 绝对航向与相对 Yaw

领域模型同时保存两个肯定事实：

- `true_heading_deg`：MS-6222 输出的绝对航向，范围 `[0, 360)`，保留 GNSS/INS 有效性和标准差。
- `relative_yaw_deg`：`wrap(true_heading_deg - center_heading_deg)` 后再应用安装坐标变换，表示摇摆台相对中心的 FRD Yaw。

摇摆台控制命令继续使用相对 FRD Yaw。客户弹窗同时显示“绝对航向”和“相对 Yaw”；曲线、误差和自动测试使用相对 Yaw。首版不把绝对航向值直接作为平台位置命令。

若后续需要“转到绝对航向”，单独提供目标航向动作：先计算最短航向差，再验证差值处于平台 Yaw 行程内，最终仍向平台发送相对角度，并由 MS-6222 绝对航向回读确认。

## 5. 进程级共享夹具运行时

新增 `FixtureRuntime`，由 `MainWindow` 创建并注入 Customer 与 Production：

- 唯一拥有 `FixtureControlLease`、`Ms6222ControlLease`、运动控制 worker、MS 串口 worker、夹具档案 Store、标定 Store 和实时状态 Store。
- Customer 弹窗、Production 批次和 Engineering 调试只向 Runtime 申请 owner，不直接创建物理连接。
- Runtime 状态包含连接、身份、标定、参考质量、控制 owner、平台状态、当前目标、相对姿态、绝对航向、误差和最近证据时间。
- Production 批次取得 owner 后，客户弹窗保留只读状态并禁用控制；工程会话和批次之间继续互斥。
- 页面关闭只停止呈现；物理连接和正式批次继续由 Runtime 生命周期管理。
- 应用退出时执行受控停止、回中策略和证据收尾；急停仍由实体急停完成。

## 6. 客户工作区摇摆台弹窗

客户总览增加“摇摆台”入口，弹窗包含：

- 型号、档案 revision、控制器地址、MS 串口、标定 ID 和当前 owner。
- 平台连接、MS-6222 连接、参考有效性和告警。
- 当前相对 Roll/Pitch/Yaw、MS 绝对航向、目标姿态和三轴误差。
- 目标相对 Roll/Pitch/Yaw、到位时间、发送姿态、回中和受控停止。
- “MS 姿态验证”和“启用外环修正”两个独立状态；发送成功、平台停止、参考验证分别显示。
- 历史短曲线只消费 Runtime Store，不另外采集串口。

回原点、参数修改和资格标定保留在 Production 工程页面；客户弹窗不暴露这些维护动作。

## 7. MS-6222 姿态外环

### 7.1 控制结构

- 供应商伺服位置环保持为内环。
- 上位机以逻辑目标轨迹作为前馈，以 MS-6222 相对 FRD 姿态误差作为低带宽外环修正。
- 使用四元数姿态误差，避免欧拉角跨越和三轴耦合造成错误差值。
- 首版使用限幅比例修正和死区，不引入积分；通过阶跃与正弦稳定性验证后再评估积分项。
- 控制周期默认 40 ms，可配置但不得短于 20 ms；迟到点直接跳过并计入证据，不补发过期目标。

### 7.2 安全门禁

以下任一条件出现时停止后续修正并进入明确状态：

- MS-6222 帧陈旧、姿态无效、航向质量不满足或标定失效。
- 平台反馈陈旧、控制器重启、伺服故障或 owner 变化。
- 姿态误差连续增大、修正饱和、超过姿态/速度/加速度限制。
- 调度跳点率、观测滞后或误差超过当前工程门限。

外环停止后不自动重放目标；操作者或正式流程必须显式回中/恢复。所有修正目标、参考样本、误差、限幅和停止原因写入夹具证据。

### 7.3 分阶段验收

1. 静态目标验证：平台停止后 MS-6222 独立确认姿态。
2. 有限次数微调：每轮稳定后计算一次有界修正，证明误差收敛。
3. 低频单轴连续外环：分别验证 Roll/Pitch/Yaw。
4. 三轴组合外环：验证稳定性、幅值、相位、残差和跳点。
5. 正式工况只在上述阶段通过后启用；否则继续使用前馈轨迹和 MS 独立评价。

## 8. 正式自动化执行器

新增 `ProductionRunCoordinator`，成为批次 attempt 状态和夹具动作的唯一 owner：

1. 冻结产品模板、设备身份、工作站档案、夹具标定和软件版本。
2. 校验电源身份并确认输出关闭。
3. 取得摇摆台、MS-6222 和电源 owner，确认平台中心、参考稳定和证据写入就绪。
4. 开启电源并确认实测电压；等待每台 DUT 新启动实例、身份和录制状态。
5. 自动执行固件与参数核对。
6. 执行静态捕获/锁定窗口，按每台设备独立判定 SNR、锁定、GNSS、姿态和连续性。
7. 执行锁定后摇摆窗口；共享一次物理轨迹，每台设备独立产生 attempt 和报告章节。
8. 执行摇摆中上电：先关闭并验证电源，平台进入指定动态轨迹，再开启并验证电源，分别记录启动、收敛和锁定恢复。
9. 执行“台架动态模拟”轨迹；报告明确标记为台架模拟，不替代真实车辆道路测试。
10. 真实车辆工况继续使用人工门禁、倒计时和证据窗口。
11. 回中、关闭并验证电源、释放 owner、冻结设备和夹具证据、计算 attempt、生成每台设备 V1 报告。

任何共享夹具故障使相关共享窗口进入 `INCOMPLETE`；单台 DUT 指标失败只改变该设备 attempt，不改变其他参与设备的独立结论。

## 9. 首个可运行闭环

首轮正式自动化限定为：

- 固件核对。
- 参数核对。
- 静态捕获与锁定。
- 锁定后摇摆。
- 摇摆中上电和重新锁定。
- 回中、断电、证据归档和每台设备报告。

GNSS/IMU/INS 汇总复用上述窗口。台架动态模拟和真实车辆工况在首轮稳定后追加，不阻塞前三种核心工况打通。

## 10. 实施顺序

1. 建立 `FixtureRuntime`、状态 Store、进程级租约和现有页面迁移，删除页面级重复 owner。
2. 扩展标定安装身份、快速复核、配置包导入导出和迁移测试。
3. 增加绝对航向/相对 Yaw 双模型和客户摇摆台弹窗，先交付开环控制加 MS 独立验证。
4. 实现静态有界修正和低频连续外环，完成三轴稳定性真机验收。
5. 实现 `ProductionRunCoordinator` 和首个三工况自动流程。
6. 接入每台设备时间窗分析、共享证据切片、报告工况曲线和阶段结论。
7. 完成异常恢复、应用退出、断网、参考失效和电源失败回归。
8. 更新翻译、用户文档、AGENTS 架构说明并执行全量测试与 Windows 真机验收。

## 11. 交付边界

- 当前 MS-6222 时间基准仍为主机串口到达时间，动态相位和延迟保持 `ENGINEERING_ONLY`。
- MS-6222 绝对航向质量取决于双天线基线、GNSS/INS 状态和安装环境；质量无效时不进入航向闭环。
- 台架动态模拟不声明等同于真实车辆、海况或更高等级运动模拟器。
- 上位机外环不绕过实体急停、平台保护范围和供应商伺服故障状态。
