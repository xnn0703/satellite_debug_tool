# M55 v1.9.1 发版计划

日期：2026-11-02。目标是将已完成并验证的 M54 自动化跟踪判据、连续摇摆时序、完整采集恢复合同、AFD01B2 24 V / 8 A 预置及报告语义作为 v1.9.1 发布。源码和 tag 使用 GitHub `github` 远端；Windows user/ops 由 GitHub Actions 构建并上传阿里云候选区，macOS user/ops 由本机 Python 3.11 构建并上传同一候选区。

## 发布范围

- M54 跟踪判据唯一 owner、逐项时间窗口、持续摇摆与共享供电恢复准备。
- 产品预置 R2：AFD01B2 24 V / 8 A；C/D 24 V / 5 A；12 V 版本 9 A。
- 生产配置、进度投影、报告性能/执行/数据质量三类结论及审核门禁。
- 完整采集租约、会话恢复及相邻回归。
- 配套中文翻译、操作指南、M50/M54 计划、验收、开发记录和 AGENTS 架构说明。

不把软件测试和冻结 smoke 解释为真实电源、摇摆台、RF、Windows 原生显卡或现场遮挡门限验收。

## 执行顺序

1. 审计工作区范围、版本源、tag、远端和服务器发行配置；确认 v1.9.1 尚未存在。
2. 更新唯一版本源和发行 SOP，运行 `git diff --check`、翻译检查、compileall、专项及全量 pytest。
3. 对审计范围做单一发布提交，推送 GitHub `master`，创建并推送不可变 tag `v1.9.1`。
4. 监控 GitHub Actions 的 Windows user/ops 测试、冻结构建、smoke、候选归档和阿里云上传。
5. 在相同源码 SHA 上构建并上传 macOS user/ops 候选。
6. 核验四份候选的版本、edition、平台、架构、源码 SHA、CRC 和 SHA-256；随后执行 ops TUF 晋升及 user 完整包公开。
7. 逐个 HTTPS 回验四份完整包，保存 v1.9.1 发行验证记录和直链。

## 发布策略

- user 版只提供人工完整包，不进入应用在线更新渠道。
- ops 版进入 stable TUF 更新渠道；完整包始终保留，差量仅在工具基于已发布 v1.9.0 基线安全生成且验证通过时发布。
- GitHub 保存源码和 tag；阿里云 HTTPS 是 v1.9.x 正式二进制分发入口。
- 已发布 tag、候选和公开文件不可覆盖；失败时修复后使用新版本。
