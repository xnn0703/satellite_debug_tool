# M19-A.8 灵境平台服务集成验收标准

## A. 资源与参数

- [x] Windows 发行包包含固定版本的平台服务资源和逐文件 SHA-256 清单。
- [x] 运行目录使用用户目录中的可写路径，不从 PyInstaller 内部目录直接运行。
- [x] 运行时 `配置/plat.xml` 与用户原始文件的 SHA-256 `eaead18830af2ce2799c73f47d7197954eb26b02f8d95c616949203ec190d761` 一致。
- [x] 厂家服务包附带的示例 `plat.xml` 不覆盖当前型号参数。
- [x] 资源缺失或哈希不匹配时禁止启动并显示具体文件。

## B. 自动启动与状态

- [ ] 操作者只启动 `SatelliteDebugTool.exe`，首次使用摇摆台时平台服务自动启动。
- [x] 已有受支持服务监听 UDP 9800 时复用，反复进入页面不创建重复实例。
- [x] 未配置本机 `192.168.15.101` 时给出明确配置提示，不把 `192.168.15.201` 当成本机服务地址。
- [x] 未知进程占用 UDP 9800 时拒绝接管并显示占用事实。
- [x] 界面分别显示进程运行、UDP 监听和远程服务要求；UDP 发送不显示为平台已运动。
- [x] 服务异常退出后平台控制进入失败状态，停止开始新的动作会话并保留退出证据。

## C. 生命周期

- [x] 软件只管理自己启动的服务实例，不关闭启动前已有的实例。
- [ ] 主程序退出前先完成夹具停止和控制租约释放，再请求受管服务正常退出。
- [x] 正常退出无法确认时不强制杀死运动控制进程，并记录可复核原因。
- [x] JSONL 日志记录服务状态、PID、owner、运行目录、时间和事件 ID；资源及配置哈希由固定 manifest 保存。
- [x] 摇摆台页面可导出单个诊断 ZIP，包含应用日志、服务事件、厂家日志、运行配置、资源清单、网络快照和逐文件 SHA-256。
- [x] 厂家日志不存在或正在写入时，诊断包仍生成并在摘要中记录缺项。

## D. 打包与真机

- [ ] 已确认厂家二进制的再分发授权，或发行范围明确限制在获授权的内部工作站。
- [ ] Windows 干净环境验证 .NET Framework 依赖、相对配置、日志目录和隐藏/最小化启动模式。
- [ ] 真机验证低幅单轴运动、MS-6222 姿态变化、停止、异常退出和再次启动恢复。
- [ ] 全量 pytest、翻译检查和 Windows PyInstaller 构建通过。

## E. 内部实现门槛

- [ ] 已取得底层控制器协议或正式 SDK。
- [ ] 已定义运动学、限位、回零、急停、伺服和故障恢复合同。
- [ ] 新服务与厂家服务完成正常、边界和故障场景对照验收后，才能替换厂家服务。
