# M19 小批试产批量测试工作站验收标准

> 日期：2026-08-09
>
> 状态：待确认、未实施
>
> 计划：`doc/M19_batch_production_test_station_plan.md`

## A. 批次与配方

- [ ] 可创建批次并记录批次 ID、配方、操作员和输出目录。
- [ ] 固件与参数标准可由 UI 录入或 JSON 导入，并在批次开始后锁定。
- [ ] 配方具有 schema、修订号和 SHA-256，报告引用同一份不可变快照。
- [ ] 参数支持类型、容差、范围、枚举、忽略和逐设备覆盖。
- [ ] 阈值缺失时相关测试不得开始或自动通过。
- [ ] 配方明确区分收敛阶段与有效观测阶段；正式持续性工况的有效观测时间均不小于 3 600 s。
- [ ] 少于正式时长的调试配方只能生成带 `ENGINEERING_ONLY` 标识的结果，不得生成正式 PASS 报告。

## B. 多设备连接

- [ ] 一个共享 UDP socket 可发现并维持最多 4 台 AFD01。
- [ ] 设备未上电时可预先开始探测和预置录制；上电后自动建会话。
- [ ] 会话按 SN 标识并按 endpoint 分流，重复 SN/IP 冲突明确阻止启动。
- [ ] 单台掉线、重启或失败不清空其他设备状态和录制。
- [ ] 未知型号、超出容量和不支持试产能力的固件显示明确原因。

## C. 流程状态机

- [ ] 九项测试按配方顺序显示准备条件、操作提示和自动判定。
- [ ] 同一电源、载具和摇摆台上的设备共享一个夹具动作 ID，但每台独立计时和出结果。
- [ ] 共享动作开始前，所有目标设备录制器均已 ARMED，未满足前置条件的设备不会悄悄加入判定。
- [ ] 单台掉线或失败只影响该设备；夹具故障、安全异常或人工急停中止整个共享动作。
- [ ] 单台补测创建新 attempt 和新夹具动作，其他设备的既有结果不被覆盖。
- [ ] PASS、FAIL、INCOMPLETE、SKIPPED、ABORTED 含义稳定且可追溯。
- [ ] 重测新增 attempt，不覆盖原始失败或中断记录。
- [ ] 人工改判必须填写原因，报告保留自动结果与人工决定。
- [ ] 持续性工况内部记录 `PREPARING / CONVERGING / EFFECTIVE_OBSERVATION / FINISHING`，阶段边界可从数据库和 SDB 重建。
- [ ] 达到收敛门限并连续满足驻留时间后才开始 60 min 有效观测；收敛耗时不占用该窗口。
- [ ] 有效观测开始后的失锁、降级和重捕继续计时并作为被测结果；夹具失效、车辆工况失效或证据流中断使结果为 `INCOMPLETE/ABORTED`，不得暂停计时规避异常。

## D. 版本和参数预检

- [ ] APP/Boot/协议版本按配方规则比较，期望与实测同时保存。
- [ ] 参数表只读获取并类型化比较，不因格式化字符串造成误判。
- [ ] 缺失、额外、类型错误和值不符逐项展示并进入报告。
- [ ] IP 等逐设备参数按覆盖规则核验。
- [ ] 预检过程不写参数、不执行 OTA、不改变射频或发射状态。

## E. 跟踪测试

- [ ] 冷启动静置在导航/姿态/锁定稳定收敛后连续观测至少 60 min，并复用同一窗口完成静态 GNSS 和 IMU 指标。
- [ ] 锁定后摇摆包含渐入/渐出过程，组合正弦稳态有效观测不少于 60 min，并统计保持率、最长失锁、重捕、SNR 和动态姿态响应。
- [ ] 摇摆中上电以 Boot Session 为起点，不把普通丢包当作重启；完成导航/姿态/锁定收敛后继续摇摆至少 60 min。
- [ ] 原地锁定后行驶的有效路线窗口不少于 60 min，并统计锁定、SNR、GNSS、速度、轨迹和姿态趋势。
- [ ] 行驶中上电记录启动到导航/姿态/锁定的分级收敛时间，稳定收敛后继续有效行驶至少 60 min。
- [ ] 五个物理工况共享四台设备并行执行，版本/参数、GNSS 和 IMU 指标不额外重复串行计时；批次开始前显示约 5 h 加收敛/换场时间的预计完成时间。
- [ ] 无外部真值时报告不宣称绝对指向精度。

## F. 共享夹具与动作证据

- [ ] `FixtureCoordinator` 是唯一可操作局域网电源和摇摆台的对象，不存在四个设备会话并发发送冲突命令。
- [ ] 灵境平台 UDP V0.3 的 A6/A6T 帧由类型化序列化器生成，格式、单位和参数数量有 golden-vector 测试。
- [ ] 回中 golden vector 为 Roll/Pitch/Yaw/X/Y=0、Z=100 mm；复位为全部 0，二者不会混用。
- [ ] 流程中止默认发送回中动作，不自动发送 Z=0 复位动作。
- [ ] 平台端点、回中/复位姿态、轴符号、软限位、最大单步变化和最短完成时间均来自带版本的夹具配置。
- [ ] `A6T` 完成时间是唯一速度控制量；每个运动段均有明确 `duration_ms`，不存在冲突的独立速度字段。
- [ ] 越界、无配置、未预检或安全门禁未确认时拒绝运动命令。
- [ ] 定时姿态命令按完成时间加保护余量顺序发送，不预灌整条曲线，也不在未确认幂等性时自动重试。
- [ ] 每条平台命令记录原始帧、目标姿态、计划完成时间、发送结果、主机单调时间和全局动作 ID。
- [ ] UI 和报告严格区分 `COMMAND_SENT`、`MOTION_OBSERVED` 与 `POSE_VERIFIED`；UDP `send` 成功不得显示为平台到位。
- [ ] 首次硬件接入在 Z=100 mm 工作高度完成低幅度单轴点动，明确 Roll/Pitch/Yaw 正方向、回中/复位位置和左右手系，并保存标定版本/哈希。
- [ ] 无独立位置回读时，至少由参考 IMU、多 DUT 姿态共识或人工确认观察到运动；证据不足时相关步骤不得自动 PASS。
- [ ] MS-6222 仅作为共享测量反馈，不参与平台实时伺服、安全或急停闭环；四台 DUT 断电期间参考模块和采集链持续独立供电、不中断同一时间线。
- [ ] 普通中止只描述为“已发送中立姿态”；没有设备反馈时不得显示“已回零”或“已急停”，现场具备独立物理急停。
- [ ] 车辆测试仅由人工驾驶，上位机记录开始/结束确认、操作员和 GNSS 辅助证据，不宣称自动控制车辆。
- [ ] 60 min 摇摆在 10 Hz 配置下可持续调度约 36 000 条 A6T 命令；调度使用绝对单调时间，过期点跳过而不突发补发。
- [ ] 每个摇摆 attempt 保存命令抖动、跳点数、最长发送间隔和有效覆盖率；任一指标超出配方门限时结果为 `INCOMPLETE`。

## G. GW Instek PSW 电源闭环

- [ ] 驱动明确识别 GW Instek PSW 80-27，TCP 端口固定为 2268、按 LF 组帧；厂家/型号不匹配时拒绝控制。
- [ ] `*IDN?` 保存厂家、型号、SN 和固件，原始字符串与解析结果进入批次证据。
- [ ] 单 TCP 连接只允许一个待响应查询；TCP 分片、粘包、额外响应、超长行、超时和重连均有自动化测试。
- [ ] SCPI golden vectors 覆盖身份、电压/电流设定与读回、`OUTP`、`MEAS:ALL?`、`*OPC?`、CV/CC、告警、保护和错误队列。
- [ ] 自动化预检要求 F-36/F-57 已启用且 F-92/PON 为 OFF；输出状态、保护或身份未知时不得 ARMED。
- [ ] 设置电压/电流前先闭环确认输出 OFF；写入后必须完成 `*OPC?`、设定值读回和错误队列检查。
- [ ] 上电证据依次为 `COMMAND_SENT / OUTPUT_STATE_CONFIRMED / VOLTAGE_CONFIRMED / DUT_BOOT_OBSERVED`；前三层是共享动作，每台设备只在自己的新 Boot Session 到达后开始收敛计时，单台超时不阻塞其余设备。
- [ ] 断电必须同时满足 `OUTP?=0`、实测电压低于配方阈值、断电驻留时间完成和目标设备离线；下一次上电必须看到新的 Boot Session。
- [ ] 断电驻留结束后仍有任一目标设备在线时阻止再次上电，并明确提示检查外部供电、回灌或设备离线判定。
- [ ] TCP 断线或应用重启后状态为 `UNKNOWN`，只查询重建状态，不自动重放 `OUTP 1` 或设定值。
- [ ] 长时测试周期记录实测电压、总电流、CV/CC、Questionable Status、保护和错误；越界/限流/保护按配方形成 FAIL 或 INCOMPLETE。
- [ ] 报告明确总电流是四台共享值，不平均成单台功耗；单台上电由各自 Boot Session/数据流判断。
- [ ] 四个 DUT 支路具有经审核的保险丝或电子保护；PC/网络故障时仍可通过实体 OUTPUT/急停或独立安全回路断电。
- [ ] MATLAB 样例中的 14 V/2 A 在正式配方批准前不得作为试产默认值。
- [ ] 电源配方显式包含身份白名单、设定值与容差、实测电压/总电流窗口、断电阈值、轮询/超时、OVP/OCP 策略和 `off_dwell_s`，批次开始后不可变。

## H. GNSS、IMU 与姿态性能

- [ ] GNSS 分别统计解算卫星、锁定信号和原始记录，不混成一个数量。
- [ ] GNSS 报告包含 Fix 连续率、C/N0 分布、位置/速度连续性和数据缺口。
- [ ] 有测量基准点时可计算水平/高程误差；无基准时只报告稳定性。
- [ ] AFD01 提供 Boot Info、Test Capabilities 和类型化 IMU 静态结果。
- [ ] 每颗 IMU 报告样本率、丢样、温度、三轴均值/标准差和重力模长误差。
- [ ] 缺报、样本不足、窗口中移动或数据无效均不得判为通过。
- [ ] 独立参考 IMU 的安装方向、坐标变换、时间偏移、标定版本和有效期均进入批次证据；未完成标定时不得作为姿态真值。
- [ ] MS-6222 实测硬件、正式固件、协议 schema 和配置均在白名单内；固件至少包含天线轴向、连续转动和运动中启动相关修复，未验证 beta 不得用于正式 PASS。
- [ ] 双天线实际基线、主从天线方向、杆臂、刚性安装和开阔收星条件均已验收；不足 2 m 时不得直接引用手册的 0.1° 航向指标。
- [ ] 参考模块关闭车辆动力学约束，不输入轮速；原始坐标、平台坐标和 DUT 坐标之间使用带版本/哈希的四元数变换，逐轴正反向测试确认符号和旋转顺序。
- [ ] 隔离 RS-422 以 460800 baud 持续采集 `INSPVAXB 100 Hz`、`GNSS 10 Hz` 和 PPS；原始帧、CRC、接收单调时间、PPS 与解析 schema 可追溯。
- [ ] 建立 MS-6222 GPS/PPS、主机单调时间和 AFD01 设备时间的时钟模型，并保存偏移、漂移、残差和有效区间；未达到配方时延/抖动门限时动态姿态结果为 `INCOMPLETE`。
- [ ] 参考有效门控至少检查时间状态、INS 导航状态、三轴姿态标准差；需要航向真值时还检查航向有效位、基线长、从天线卫星数和航向标准差。无效段不跨越插值。
- [ ] MS-6222 资格验证覆盖不少于 2 h 静态、三轴逐轴正反向、`±1°/±5°/±15°`、`0.05~0.3 Hz`、60 min 组合轨迹、运动中上电不少于 20 次，以及至少一次更高等级参考对比。
- [ ] 资格记录给出参考重复性、动态时延、有效覆盖率和测量不确定度。参考能力不足以覆盖 DUT 验收门限时，只报告数值/趋势，不给绝对姿态 PASS 或 `POSE_VERIFIED`。
- [ ] 有参考真值时按姿态误差四元数计算连续三轴误差，报告均值、标准差、RMS、P95、P99、最大值和峰峰值。
- [ ] 每个 60 min 工况报告首 5 min 与末 5 min 中位数差、稳健趋势斜率（deg/h）和三轴漂移向量模，并把后者定义为综合姿态漂移。
- [ ] 动态工况报告幅值比、主频误差、相位差/时延和残差 RMS，且平台命令到参考 IMU、参考 IMU 到 DUT 两级误差分开计算。
- [ ] 收敛时间至少区分导航就绪、姿态首次/稳定收敛、首次/稳定锁定；稳定收敛必须持续满足配方驻留时间。
- [ ] 无独立参考 IMU 时，报告字段只能命名为输出相对漂移、输出稳定时间和多 DUT 共识偏差，不得标记为绝对姿态误差、综合姿态漂移或真实收敛精度。

## I. 录制与数据质量

- [ ] 每台设备独立生成 SDB v3，不把多台原始帧混入同一个文件。
- [ ] SDB 包含批次/配方/设备身份、测试边界、人工动作和控制记录。
- [ ] 每台 SDB 均引用相同的共享夹具动作，批次保存可重建的电源/平台/车辆时间线。
- [ ] 上电前 ARMED 后即可记录最早收到的帧，身份确认后安全归档到 SN 目录。
- [ ] 队列丢弃、离线区间、未恢复 capture profile 和不完整 footer 可见。
- [ ] 任何证据不完整使相关测试或总结果为 `INCOMPLETE`。
- [ ] 原始 SDB 保留全量采样；报告曲线使用可追溯的 min/max/median 时间桶或视觉降采样，不因 60 min 窗口截断关键峰值。
- [ ] 正式批次开始前按首分钟实测码率、剩余工况和安全系数估算磁盘需求，空间不足时阻止启动。

## J. 报告

- [ ] 每台设备生成 PDF、HTML、JSON 和对应 SDB 证据。
- [ ] 报告包含身份、配方哈希、版本/参数差异、所有 attempt 和阈值/实测/结论。
- [ ] 报告按物理工况列出有效观测时长、收敛耗时、三轴/综合漂移、动态幅频相位、锁定、SNR、GNSS、温度和数据完整性指标。
- [ ] SNR 报告包含中位数、P5/P95、相对静态基线变化、趋势斜率、低于阈值累计/最长连续时间；锁定报告包含可用率、失锁次数/时长和重捕 P50/P95/最大值。
- [ ] 报告包含 GNSS/轨迹、IMU 静态统计以及 PLL、组件状态、温度与姿态/SNR 异常的关联时间线。
- [ ] 报告包含共享电源与平台动作、电源设定/实测/CV-CC/保护、发送/观察/验证证据等级及平台无回读限制说明。
- [ ] 报告明确注明姿态参考来源和证据等级；无真值时不使用可能被理解为绝对性能的字段名称。
- [ ] 批次生成 CSV 汇总并能定位到每台设备产物。
- [ ] 关闭应用后可从 SQLite + SDB 重建相同结论和报告。
- [ ] 报告生成失败不会把批次标为完成。

## K. 自动化与平台验证

- [ ] 配方、状态机、指标、持久化、恢复、报告和协议具备单元测试。
- [ ] 全量 `PYTHONPATH=. pytest satellite_debug_tool/tests -q` 通过且无新增 warning。
- [ ] AFD01 app debug/release 构建通过，资源与栈满足现有安全余量。
- [ ] 1024x600、1280x800、Windows 125%/150% DPI 下四机页面可用。
- [ ] 四台设备同时 20 Hz 产品数据及全量录制覆盖完整约 5 h 正式流程，无会话串线、UI 卡顿、存储耗尽和未解释的 SDB 丢帧。
- [ ] 四台设备在同一平台上完成共享摇摆和统一上电流程，动作窗口在四份报告中一致且设备判定相互独立。
- [ ] MS-6222 在完整约 5 h 批次中持续输出，DUT 断电和摇摆中上电不触发参考重对准；参考失效能使相关窗口明确 `INCOMPLETE`，不会静默回退到平台命令真值。
- [ ] PSW 真机完成身份拒绝、输出 OFF 预检、闭环 ON/OFF、断电驻留、保护/限流、TCP 断线重连和应用重启状态恢复验收。
- [ ] 真实小批按正式 SOP 完成，并由人工抽查报告与原始证据一致。

## 通过规则

主机单测和固件构建只构成软件验证。M19 必须完成平台轴向/限位、MS-6222 坐标/时间/精度资格验证、PSW 输出闭环与四路支路保护验收、4 台真机约 5 h 完整流程、九项结果复核和至少一批真实小批报告复核后，才能标记为试产可用。若 MS-6222 未配置、资格过期或参考能力不足，姿态相关验收只能按文档限定的相对指标执行。
