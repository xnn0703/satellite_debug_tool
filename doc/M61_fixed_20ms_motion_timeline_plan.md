# M61 摇摆台固定 20 ms 连续轨迹计划

> 历史方案：M68 已确认第 7 行把本项目夹具会话抓包误记为厂家原上位机抓包。当前合同为 macOS 20 ms、Windows 50 ms，本文件不再作为现行实现依据。

## 1. 根因证据

- 现场抓包 `摇摆台test.pcapng` 的连续运行段共有3,541个控制指令，P95/P99为51.204/51.373 ms，最大66.387 ms；控制器反馈最大21.405 ms、六轴伺服错误为0，发送链路不是持续异响的主要来源。
- 对应会话 `20261103T103048-b56bf3db` 使用 Roll/Pitch 15°@0.25 Hz、Yaw 10°@0.1 Hz；50 ms离散轨迹的单缸目标步长P95为5.82 mm、最大6.08 mm。
- 厂家原上位机抓包 `摇摆台.pcapng` 使用约20.24 ms周期且位置命令时长字段固定20 ms。用户确认连续轨迹周期不再提供配置，产品合同固定为20 ms。

## 2. 单一模型

1. `CONTINUOUS_TRAJECTORY_PERIOD_MS = 20` 是连续正弦轨迹周期的唯一权威事实。
2. `SineTrajectory` 不再接收周期构造参数，只提供只读 `sample_period_ms` 投影。
3. 预编译控制帧的动作时长固定为20 ms，不再使用周期1.2倍覆盖或工位可编辑最短动作时间推导。
4. 工程摇摆台页面删除采样周期控件和标签；预览、姿态关联和报告均消费同一常量。
5. 新生产配方保存20 ms证据字段，配方校验要求该字段等于20；正式执行不从配方读取可变周期。
6. 真实UDP继续由独立spawn进程独占发送；晚唤醒保存证据、发送当前点并从真实发送时刻重建周期，不突发追赶。

## 3. 验证

1. 协议帧断言动作时长为20 ms，轨迹构造不存在周期输入。
2. 页面断言无采样周期编辑控件，生成轨迹固定20 ms。
3. 生产配方与正式硬件轨迹固定20 ms，其他周期明确拒绝。
4. loopback UDP以20 ms发送不少于100点，父进程证据消费与缓停回正正常。
5. 运动、夹具、生产和翻译定向回归后执行全量测试。
6. 现场先以10°三轴运行10 min，再执行15°工况，对比pcap、MS-6222与机械声音。

## 4. 证据边界

- 软件测试证明固定合同、调度隔离和数据流一致性。
- macOS不是实时系统；只有新pcap能证明现场P95/P99和最大间隔。
- 只有机械观察与MS-6222能确认20 Hz周期异响是否消失；若仍存在，下一步调查控制器轨迹/FIFO模式。
