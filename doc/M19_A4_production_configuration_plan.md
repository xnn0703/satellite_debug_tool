# M19-A.4 可视化试产配置与批次生成计划

## 目标

将批次测试从“手写 JSON 配方并导入”改为现场可直接操作的流程：操作者在批次页面选择产品型号、设备数量和工作站配置，软件根据已保存的产品测试模板和夹具档案自动生成本批次的不可变配置快照。

以 `AFD01C × 2` 为首个明确示例：若产品模板配置单台供电需求为 `12 V / 8 A`，批次自动得到 `12 V / 16 A / 192 W`，并要求启动时恰好识别到 2 台 AFD01C。

配置通过软件设置维护，支持导出和导入，其他工作站无需手写 JSON 即可复用。底层仍保存带 schema、revision 和 SHA-256 的快照，保证报告可追溯。

## 当前事实

- 批次页面目前要求导入 `ProductionRecipe` JSON，没有产品数量选择。
- 配方中的 `fixtures.power_profile` 目前只是非空字符串，没有电源档案解析、容量检查或正式批次控制链。
- 批次启动门禁当前接受一台或多台匹配产品，启动时冻结当时在线参与者，没有与操作者声明的目标数量比较。
- 当前已验证的自动电源驱动只有 GW Instek PSW80-27；电源调试页已具备身份识别、自动验证限制和 OUTPUT ON/OFF 闭环。
- 摇摆台已有带 revision 与 SHA-256 的 `FixtureProfileStore`，可以沿用“档案由设置维护、批次引用并冻结快照”的模式。

## 领域模型

### 1. 产品测试模板

新增版本化的产品测试模板，至少包含：

- 稳定 `template_id`、显示名称、revision、schema version 和 SHA-256。
- 注册产品 ID，例如 `afd01`、`afd01c`。
- 单台供电需求：电压、电流上限。
- 固件与设备参数期望。
- 默认测试项目、测试时长和判定参数。
- 所需夹具能力，例如电源、摇摆台、参考设备和人工车辆门禁。

产品模板表达产品和测试要求，不保存某台工作站的 IP、端口或仪器 SN。

### 2. 电源档案

新增版本化的电源档案，至少包含：

- 稳定 `profile_id`、显示名称、revision、schema version 和 SHA-256。
- 驱动 ID；首版只注册 `gwinstek_psw80_27`。
- 厂家、型号、可选 SN、IPv4 和 TCP 端口。
- 额定电压、电流和功率。
- 输出稳定超时及驱动支持的自动验证策略 ID。

型号下拉框只列出已注册驱动。首版只有 GW Instek PSW80-27；未知型号不能伪装成通用 SCPI 电源。

### 3. 工作站配置

新增工作站配置，将当前工作站可用的电源档案、摇摆台档案、参考设备档案和支路能力组合为一个可选择对象。至少记录：

- `station_profile_id`、显示名称、revision 和 SHA-256。
- 电源档案引用。
- 摇摆台档案引用。
- 参考设备配置引用。
- 可用独立供电支路数量及每支路允许电流。

批次只引用一个工作站配置，创建时解析所有引用并冻结完整快照；运行过程中修改设置不改变已创建批次。

### 4. 批次请求与不可变快照

批次页面收集：

- 产品模板。
- 设备数量，首版范围 `1..4`。
- 工作站配置。
- 操作者、批次号和输出目录。

软件生成不可变批次快照，包含：产品、目标数量、每台供电需求、合计电流/功率、测试合同、已解析的夹具档案及各项 SHA-256。现有结果库和报告只读取该快照，不读取可能已变化的实时设置。

## 计算和门禁

### 1. 电源需求

同一批次只允许一种产品型号。对于并联在同一电源上的同型号设备：

- 输出电压 = 产品模板的单台需求电压。
- 合计电流上限 = 单台电流上限 × 设备数量。
- 合计功率 = 输出电压 × 合计电流上限。
- 每支路要求 = 产品模板的单台电流上限。

首版不增加隐式裕量系数。若现场需要裕量，必须作为产品模板中的显式值并显示计算结果。

创建批次前验证：

- 合计需求不超过电源档案的额定电压、电流和功率。
- 工作站独立支路数量不少于设备数量。
- 每支路能力满足单台电流要求。
- 电源驱动支持产品需求电压和电流。

### 2. 设备数量与身份

选择 `AFD01C × 2` 后，启动门禁必须证明：

- 恰好 2 台在线、身份已确认、证据录制已就绪的 AFD01C。
- 不存在会被纳入本批次的第三台 AFD01C。
- AFD01、未知型号、身份冲突或缺少唯一身份的设备不能成为参与者。

启动后冻结这 2 台设备的不可变身份；掉线或替换设备进入明确的批次异常流程，不能静默补位。

### 3. 电源身份与状态

批次启动前必须使用电源档案建立连接并完成 `*IDN?` 匹配。电源容量计算通过只表示配置兼容；OUTPUT ON、实测电压和保护状态仍由 PSW 闭环证据确认。

## 界面

### 1. 批次测试页面

移除“导入配方 JSON”作为日常入口，改为：

- 产品型号/模板下拉框。
- 设备数量选择框。
- 工作站配置下拉框。
- 只读的自动配置摘要。

摘要至少显示：

- 产品和数量，例如 `AFD01C × 2`。
- 单台供电和合计供电，例如 `单台 12 V / 8 A；合计 12 V / 16 A / 192 W`。
- 电源型号、IP、SN 锁定和容量结论。
- 支路数量结论。
- 测试项目和总时长概要。
- 摇摆台与参考设备档案。
- 配置版本和摘要 SHA-256。

任何依赖项缺失或容量不满足时，页面直接显示具体原因并禁止创建批次。

### 2. 设置页面

在设置中增加“试产配置…”管理入口，打开独立管理窗口：

- 产品测试模板：新建、复制、编辑、删除。
- 电源档案：新建、编辑、删除、连接并识别验证。
- 工作站配置：组合已存在的档案并检查能力。
- 导入配置包、导出配置包。

首版使用表单和下拉框，不提供原始 JSON 编辑器。

## 导入导出合同

配置包使用一个版本化 JSON 文件，包含选中的产品模板、电源档案、工作站配置及其依赖：

- 包含 `schema`、`schema_version`、导出时间、应用版本和各对象 SHA-256。
- 导入前完整验证，不允许部分写入。
- 同 ID、同 revision、同 SHA-256 视为同一版本。
- 同 ID/revision 但内容不同必须报冲突，不覆盖。
- 较高 revision 需要操作者明确选择导入；保存后原子写入。
- 导入不携带上次 OUTPUT 状态、自动开启意图、批次号或现场运行证据。

## 持久化

三类配置由一个权威 Store 原子保存到：

- `~/.satellite_debug_tool/production_configuration.json`

使用一个目录文件可保证产品、电源和工作站之间的引用一起通过校验并提交，不会出现只写入一部分依赖的状态。

`settings.json` 只保存上次选择的稳定 ID，不保存这些档案的权威内容。

## 实施顺序

1. 新增产品模板、电源档案、工作站配置模型、Store、校验和配置包导入导出。
2. 为设置页增加“试产配置…”管理窗口。
3. 将批次页改为产品模板、数量、工作站配置选择，并显示自动计算摘要。
4. 从选择结果生成不可变批次快照，接入现有 ResultStore。
5. 将启动门禁改为目标产品和目标数量的精确匹配。
6. 将正式批次电源 owner 接到已验证的 PSW 适配器；保持电源调试页与批次互斥。
7. 更新翻译、用户文档、测试和开发记录。

## 不在本轮范围

- 不支持一个批次混合多种产品型号。
- 不提供任意第三方 SCPI 命令或未知电源通用驱动。
- 不自动推断启动电流裕量或把总电流除以设备数量作为单台实测电流。
- 不删除已生成批次中的不可变历史配方快照。
- 不把软件容量计算当作支路保险丝、线束和实体保护能力的验收证据。
