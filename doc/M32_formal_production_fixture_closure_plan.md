# M32 正式试产与夹具配置收口计划

## 1. 目标

把已经具备控制通路的 PSW80-27、灵境摇摆台和 MS-6222 收口为正式工作站资产，并将 M31 出货整备接入正式自动化流程：

1. 自动化测试页面可以选择并配置完整工作站档案。
2. 电源 TCP、摇摆台本机/控制器 UDP、MS-6222 串口和波特率均有明确配置来源。
3. 批次创建时冻结三个夹具的连接、身份、标定、revision 和 SHA-256。
4. 运行时显示“已配置、连接中、已连接、就绪、运行、故障”等事实状态，不再使用笼统的“待验证”。
5. 将 M31 固件/参数整备和首轮正式工况接入真实执行器。
6. 完成软件与真机验收后移除“工程预览”提示，启用正式批次放行。

## 2. 当前事实与根因

- 电源连接参数已经由 `PowerSupplyProfile` 持有，包括 IP、TCP 端口、期望身份和额定值。
- 摇摆台连接参数由 `WorkstationFixtureProfile` 持有，包括本机 IPv4、反馈端口、控制器 IPv4、命令端口、几何、包线和标定 ID。
- MS-6222 串口目前只保存在 `settings.json` 的 `production.ms6222_port`，波特率在 worker 中固定为 `460800`，没有正式 reference profile。
- `StationProfile` 目前只引用 `motion_profile_id` 和 `reference_profile_id` 字符串；`ProductionConfigurationStore.resolve()` 没有解析这两个依赖。
- 生产配置包只携带产品、电源和工作站记录，没有携带摇摆台档案、坐标标定和 MS-6222 档案。
- 批次页面选择工作站后只显示两个 ID，无法显示或冻结实际端点与 COM 口。
- `ProductionRunCoordinator` 已有明确 attempt 状态机，但还没有连接真实 OTA、参数、电源、运动、参考采集和工况分析执行器。

因此，直接删除“工程预览”或把“待验证”改成“通过”会制造没有事实来源的正式状态。收口方式是统一配置和执行 owner，然后由实际连接及回读驱动界面状态。

## 3. 正式工作站配置模型

生产配置 schema 升级为 v2，工作站选择解析以下四项依赖：

### 3.1 电源档案

沿用 `PowerSupplyProfile`：

- 驱动型号。
- IPv4 和 TCP 端口。
- 期望制造商、型号、序列号。
- 额定电压、电流、功率和稳定时间。

### 3.2 摇摆台档案

沿用 `WorkstationFixtureProfile` 作为唯一 owner：

- 型号和档案 ID、revision、SHA-256。
- 本机 IPv4 与反馈 UDP 端口。
- 控制器 IPv4 与命令 UDP 端口。
- FRD 轴转换、中心位、运动包线和几何 SHA-256。
- 已确认坐标标定 ID、标定 revision 和 SHA-256。

正式工作站不得引用 `PENDING-*` 标定。型号预置可以生成初始档案，但只有已确认标定的档案可进入正式批次。

### 3.3 MS-6222 档案

新增 `ReferenceSensorProfile`：

- 档案 ID、revision、显示名称和驱动 ID。
- 串口名称，例如 Windows `COM5` 或 macOS `/dev/cu.usbserial-*`。
- 波特率，MS-6222 当前固定合同为 `460800`。
- 安装身份 ID和可选人工确认序列号。
- 关联坐标标定 ID。
- 数据新鲜度、姿态质量和中心稳定性门限。

COM 口属于工作站安装事实，可以在本机编辑。配置包导入另一台电脑后，若原 COM 不存在，档案状态为“需要绑定串口”，不能自动猜测或静默选择其他设备。

### 3.4 工作站档案

`StationProfile` 继续作为自动化页面唯一选择项，并强制引用：

- 一个电源档案。
- 一个摇摆台档案。
- 一个 MS-6222 档案。
- 支路数量、单支路额定电流。
- 报告品牌与测试环境字段。
- M31 ProvisioningBundle 默认选择策略。

解析后的 `ResolvedProductionConfiguration` 包含四项完整快照和组合 SHA-256，不再只保存字符串 ID。

## 4. 配置界面

“管理生产配置”调整为：

1. 产品模板。
2. 出货配置包。
3. 电源档案。
4. 摇摆台档案。
5. MS-6222 档案。
6. 工作站档案。

各夹具档案均提供“测试连接”：

- 电源：连接、身份和输出关闭状态。
- 摇摆台：本机地址可绑定、反馈端点可用、控制器反馈已建立；不自动运动。
- MS-6222：列出当前串口、打开串口、收到有效协议帧和姿态质量。

自动化批次页面选择工作站后只读显示：

- 电源型号、IP、端口和身份。
- 摇摆台型号、本机反馈端点、控制器命令端点和标定 ID。
- MS-6222 COM 口、波特率、安装身份和标定 ID。
- 四项 revision、短 SHA 和整体配置 SHA。

批次创建前可以进入配置管理修改；创建后本批次使用冻结快照，不随工作站设置变化。

## 5. 配置导入导出

生产配置包 v2 自包含：

- 产品模板和 M31 ProvisioningBundle。
- 电源档案。
- 摇摆台档案。
- 被引用的坐标标定。
- MS-6222 档案。
- 工作站档案和报告品牌。

导入顺序固定为校验全部 schema、引用、revision 和 SHA-256后原子提交。相同 ID/revision 但 SHA 不同明确冲突，不部分覆盖。

导入后的串口若不存在，只将 reference profile 标记为“需要绑定串口”；其他引用和哈希保持不变。修改 COM 口产生新的 reference profile revision。

## 6. 夹具运行时收口

扩展进程级 `FixtureRuntime`，成为以下对象的唯一 owner：

- 摇摆台连接 worker、控制器反馈、轨迹调度和租约。
- MS-6222 串口 worker、协议解析、质量状态和租约。
- 电源由正式 `ProductionPowerWorker` 持有，其配置来自同一冻结工作站快照。
- 夹具状态 Store 和批次证据写入。

Production、Customer 和 Engineering 页面只申请租约、发出意图和呈现 Store，不再各自保存连接参数或创建物理 worker。`production.ms6222_port` 迁移到 reference profile 后删除为业务状态源，只保留一次性迁移读取。

## 7. 正式状态语义

夹具表使用直接事实：

- `未配置`：工作站档案没有完整引用。
- `需要绑定`：配置完整但本机 COM 或本机 IPv4不可用。
- `已配置`：快照和引用校验通过。
- `连接中`：worker 正在建立连接。
- `已连接`：通信建立，尚未满足本次运行门禁。
- `就绪`：身份、输出关闭/中心、参考质量和证据 owner均满足本次步骤要求。
- `运行`：当前步骤拥有夹具。
- `故障`：有明确错误代码和证据路径。

测试项目使用 `待执行、准备中、收敛中、采集中、分析中、PASS、FAIL、INCOMPLETE、ABORTED`。删除“待验证”“工程验证用途”等没有动作或证据来源的文案。

“资格测试”更名为“工作站夹具自检”。门限进入版本化工作站自检策略；完成后记录通过/失败和证据，不再显示“阈值仍为工程验证用途”。

## 8. 正式自动流程

在一个 `FormalProductionCoordinator` 下组合 M31 和现有 `ProductionRunCoordinator`：

1. 冻结产品、出货包、设备身份和完整工作站配置。
2. 连接电源、摇摆台和 MS-6222，执行无运动预检。
3. 确认电源输出关闭、摇摆台中心、MS 姿态质量和录制就绪。
4. 对每台设备执行 M31 固件和参数整备，达到 `ready_for_test`。
5. 开启并确认电源，确认每台 DUT 新启动实例和录制状态。
6. 执行静态捕获与锁定。
7. 执行锁定后摇摆。
8. 执行摇摆中上电与重新锁定。
9. 按产品模板选择执行台架动态模拟；真实车辆仍使用人工门禁。
10. 受控停止、回中、关闭并确认电源、冻结证据。
11. 按 M31 逐台隔离写入并确认最终出货 IP。
12. 计算每台设备结果，生成 V1 报告、evidence.zip 和 manifest。

每一步只依据设备/夹具回读和证据推进，不依据等待时间推断成功。共享夹具故障只把依赖该共享步骤的 attempt 标记为 `INCOMPLETE`，设备级 FAIL 保持独立。

## 9. 正式界面切换条件

以下软件项完成后删除生产页“工程预览”提示：

- 完整工作站配置可解析、冻结、导出和导入。
- 三个夹具由正式 runtime owner 连接并写入证据。
- M31 整备和首轮三工况执行器已接通。
- 正常、中止、断网、掉电、参考失效和设备失败均完成自动收尾回归。

以下真机项完成后把版本标记为“正式试产可用”：

- 一台真实 DUT 完成固件/参数整备、三工况、最终 IP和报告。
- 两台真实 DUT 证明共享动作一致、设备结论独立和相同出货 IP逐台确认。
- Windows 打包版在目标工位通过连续运行与异常恢复。

界面不再显示笼统“待验证”，但仍如实显示当前运行状态、未配置项和失败项。

## 10. 实施顺序

1. 升级生产配置 schema，新增 reference profile并解析摇摆台/标定依赖。
2. 完成旧 settings 和 v1生产配置的单向迁移，删除重复状态源。
3. 扩展配置管理 UI、批次工作站摘要和配置导入导出。
4. 将摇摆台与 MS 物理 worker迁入 `FixtureRuntime`。
5. 实施已确认的 M31 ProvisioningBundle 与设备整备状态机。
6. 为 `ProductionRunCoordinator` 接入真实固件、参数、静态、摇摆和上电执行器。
7. 接入报告、证据、最终 IP和正式状态文案。
8. 完成软件回归、Windows 打包和一台/两台真机验收。

## 11. 边界

- “夹具可控”表示控制通路已建立；每个正式批次仍必须执行连接、身份、中心、输出关闭和参考质量预检。
- 串口枚举不能替代设备身份。自动重绑必须有稳定硬件身份；当前没有时由操作员显式选择。
- 实体急停、伺服保护和电源保护继续由硬件负责，上位机不替代。
- 真实车辆道路测试保留人工安全门禁，台架动态模拟不声明等同真实道路。
