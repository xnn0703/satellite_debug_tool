# M42 用户版与运维版验收标准

状态：源码与 macOS 本地软件验收完成；Windows 冻结安装/更新与真实设备动作待验。用户版包含独立设备固件升级。配套：[计划](M42_user_operations_editions_plan.md)、[开发记录](M42_user_operations_editions_dev_log.md)。

## A. 用户版

- A1：默认客户导航为总览、RF 控制、客户回放、独立固件升级，侧栏提供 Shell 弹窗；中英文和三主题保持正常。
- A2：四设备目录、显式添加/编辑/删除、连接、只读状态、正常客户 RF 操作、录制及客户回放通过回归。
- A3：进程只创建用户版需要的会话、Store 与呈现 owner；电源、iperf、夹具和试产执行 owner 的数量为零；Shell 首次打开时创建，连接由用户发起。
- A4：工程/试产快捷键、命令行参数、旧配置和内部页面入口均保持 user 产物能力范围。
- A5：包内容审计与冻结运行检查证明运维专属 UI/执行模块、报告生成资源和操作入口已从用户产物裁剪。共享文件解析依赖按实际模型边界复用。
- A6：日常设置与本地数据独立归属 user；原有 ops 设置保持完整。客户设备添加方式保持现状。

## B. 运维版

- B1：完整客户页、维护/OTA、工程诊断、Shell/YMODEM、外接电源、网络测试、摇摆台/MS-6222、试产/报告功能继续可用。
- B2：协议、会话权威 owner、租约、回读确认与证据收尾合同保持现状；全量回归通过。
- B3：既有全量安装与配置按 ops 归属迁移；现有录制、设备目录、工位与报告配置完整可读。

## C. 构建与更新

- C1：相同源码版本能分别构建 user/ops；产物、清单和应用内类型可辨认，安装目录与系统身份可区分。
- C2：更新器按 edition/platform/version 精确选包。混放两个版本资产的 Release 仍分别选中本版唯一载荷。
- C3：user→ops 与 ops→user 交叉载荷安装在进入覆盖前被明确拒绝；错误包保持原安装完整。
- C4：模拟旧全量更新器的真实资产正则，证明它只获得 ops 包。旧包迁移边界在首次双版本发布时冻结并专项验收。
- C5：各包通过模型/运行资源、唯一载荷、updater 布局与签名相关检查。
- C6：提供两版体积、启动耗时、空闲内存与模块/线程清单的实测对照。

## D. 交付证据

- D1：先增加单一产物混入运维模块及按平台误选更新资产的可复现回归，再验证双版合同。
- D2：用户版四页面与运维版完整工作区在目标平台完成冻结包启动、退出、语言/主题和所需图形组件检查；受限平台明确记录待验。
- D3：全量软件测试、翻译 update/check 与差异检查通过；硬件动作的现场验证继续按既有验收要求独立记录。
- D4：计划、验收、开发记录、AGENTS.md、BUILDING.md 与发行 SOP 的最终矩阵一致。
