# M20 根因修复与状态完整性计划

## 目标

按项目最高优先级准则修复连接、能力、产品状态、夹具证据和通信边界中的根因。每个业务事实只保留一个权威来源；界面只呈现领域状态并发出操作意图；未知、过期和失败均使用明确状态表达。

## 实施范围

### 1. 握手连接代际

- 每次连接建立独立 profile 代际，首轮只请求 META。
- 当前代际收到 META 后再请求通道、状态、事件定义和语义表。
- 定义表只绑定到当前代际已确认的硬件型号；META 前到达的定义不写入缓存 profile。
- 同一连接中硬件型号变化会开启新代际并重新请求全部定义。
- ready 仅由同一代际的 META、通道、状态和事件定义共同形成。

### 2. 能力与响应合同

- capability 使用 `UNKNOWN / SUPPORTED / UNSUPPORTED` 三态模型。
- 参数、OTA 和上下文响应等敏感功能只在设备明确声明支持后启用。
- 参数、Debug 和 OTA 响应按命令上下文、参数名或分片序号精确匹配；无上下文 `OK` 不推进事务。
- 删除基于硬件名称的隐式功能启用、DATA_REPORT 代替 Debug ACK 和死重试分支。
- 旧设备兼容只允许进入具有明确版本边界和专项测试的兼容合同。

### 3. 产品状态单一来源

- 发射开关由快速状态帧作为权威来源；慢速帧仅在尚未收到快速状态时提供初始化值。
- 未知 trace mode 保持 `UNKNOWN`，不映射为自动模式。
- 状态控制绑定只由显式语义或确定的 trace-mode 名称产生，state ID 不代表控制能力。
- Product Service 订阅由匹配请求 ID 的成功响应或有效快速遥测确认。
- SNR 按字段可用性选择数据源，设备身份信息不代表实时遥测就绪。

### 4. 时间与客户呈现

- 新鲜度统一使用主机单调时间，墙钟只用于显示和记录。
- 过期状态不显示绿色成功；未知姿态不再转换为零姿态。
- 3D 姿态组件提供明确的可用/不可用状态，客户页面根据字段可用性更新。

### 5. 夹具证据链

- 平台发送成功与证据写入成功分别记录；记录失败不得改写“指令已发送”事实。
- 任一证据写入失败会进入明确的 `evidence_failed` 状态，停止接受后续动作并以 incomplete 收尾。
- UI 显示会话收尾的真实状态，incomplete 不显示为保存成功。
- 命令、事件和 MS 原始帧记录共用同一失败入口，避免递归记录故障。

### 6. 通信边界与肯定式接口

- Serial/Udp worker 只输出原始接收块，唯一的 `FrameReceiverV2` 负责组帧、CRC 和恢复。
- UDP 只接受配置的远端 IP 与端口，数据报之间不跨来源拼接。
- 删除 BaseWorker 的重复弱解析器和无调用的空实现 API。
- 更新器使用肯定式 relocation 和 update-check 配置；旧内部否定式入口退出。

## 实施顺序

1. 建立 M20 计划、验收标准和开发日志。
2. 修复握手代际、能力三态和精确 ACK。
3. 统一产品状态、订阅确认、SNR 来源和单调时间。
4. 修复客户状态呈现和夹具证据失败状态。
5. 收口通信 worker 边界并清理失效接口。
6. 更新翻译、专项测试和全量回归，逐项对照验收标准。
