# M19-A.8 灵境平台服务集成计划

## 目标

- Windows 操作者只启动 `SatelliteDebugTool.exe`，软件在需要摇摆台时自动准备并启动灵境平台服务，不再手工双击 `ProConvert.exe`。
- 保留清晰的状态边界：服务进程运行、UDP 端口监听、驱动连接、指令发送和平台实际运动分别由各自证据确认。
- 当前型号的机械和换算参数只使用用户提供的原始 `plat.xml`；厂家服务程序目录中的示例 `plat.xml` 不进入运行配置。

## 已确认事实

- `ProConvert.exe` 是 Windows 32 位 .NET Framework 4.8 WinForms 程序，依赖同目录的 `StewartPlat.dll`、其他程序集、`配置/` 和日志配置。
- 服务程序监听 UDP 9800，接收 A6/A6T 文本指令；`StewartPlat.dll` 再通过 `ECMEthcat` 驱动 `192.168.15.201`。
- 服务程序使用相对路径读取配置和写入 `log/`，启动时必须设置正确工作目录，并使用可写的运行目录。
- 当前配置关闭 `udp数据反馈`，UDP 指令发送成功不能证明驱动已接受或平台已运动。
- 用户提供的原始 `plat.xml` SHA-256 为 `eaead18830af2ce2799c73f47d7197954eb26b02f8d95c616949203ec190d761`。

## 交付路线

### 第一阶段：随附并托管厂家服务

这是当前可落地路线。服务仍由厂家二进制完成运动学换算和 EtherCAT 驱动，本软件负责资源校验、配置部署、单实例启动、状态呈现和生命周期管理。

1. Windows 发行包携带一份固定版本的平台服务资源及 `service-manifest.json`。清单记录每个运行文件的相对路径、长度和 SHA-256。
2. 首次使用时把服务资源部署到 `~/.satellite_debug_tool/vendor_services/lingjing-a6/<版本>/`。运行目录可写，PyInstaller 内部目录不直接承担运行日志。
3. 部署时强制写入用户提供的原始 `plat.xml`，并校验其固定 SHA-256；示例 `plat.xml` 不复制到运行目录。
4. `LingjingPlatformServiceController` 成为平台服务进程的唯一 owner，维护 `unavailable / stopped / starting / listening / exited / failed` 状态。
5. 进入 Production 工作区且首次使用摇摆台时自动启动服务。以 `--production` 启动时同样无需手工运行第二个 EXE；普通 Customer/Engineering 使用不启动该服务。
6. 启动前检查本机是否配置 `192.168.15.101`、UDP 9800 是否已被占用、运行文件哈希是否匹配。已有受支持实例监听时复用，不重复启动；未知进程占用端口时明确报错。
7. 启动 `ProConvert.exe` 时固定工作目录并最小化窗口。是否可把厂家 `showform` 设置改为完全隐藏，留待 Windows 真机确认隐藏模式不影响驱动初始化后决定。
8. 平台页面显示服务版本、PID、配置哈希、端口监听和退出原因。`listening` 只表示服务端口就绪，不显示“平台已连接”或“运动已执行”。
9. 本软件只关闭自己启动的服务。退出前先完成夹具停机和资源释放，再请求服务正常退出；不能确认正常退出时保留进程并记录原因，不强制杀死运动控制进程。
10. 摇摆台页面提供“导出诊断包”，将应用日志、服务事件、厂家日志、实际运行配置、资源清单、网卡地址、IPv4 路由和 UDP owner 汇总为单个 ZIP。导出操作不修改运行配置和服务状态。

### 第二阶段：内部服务实现

完全替换厂家程序需要获得或补齐以下合同：

- `192.168.15.201` 控制器的传输协议、寄存器/命令表和连接恢复规则。
- 六自由度运动学、限位、插补、回零、急停、伺服使能和故障复位状态机。
- 驱动接受、执行完成、轴状态和错误码的确定性回读接口。
- 厂家认可的边界样例、故障注入方法和真机验收规程。

只有 A6/A6T 上层协议和现有 DLL 名称不足以证明等价实现。取得上述资料后，再选择纯 Python owner、独立 C# headless helper，或由厂家提供的正式 SDK；新实现通过对照测试后直接替换厂家进程，不长期保留两套控制 owner。

## 打包与授权边界

- 技术上可将厂家目录纳入 Windows PyInstaller onedir 发行物，但仓库和公开发行包加入第三方 EXE/DLL 前，需要确认厂家允许随产品再分发。
- macOS 构建不携带也不启动该 Windows .NET Framework 服务。macOS 若要直接驱动平台，需要第二阶段的跨平台后端合同。

## 测试

- 单元测试覆盖资源清单、原始 XML 固定哈希、部署原子性、单实例判定、状态迁移、异常退出和 owner 退出规则。
- UI 测试覆盖自动启动状态、端口占用、缺少本机 `.101` 地址、资源损坏和服务退出提示。
- 诊断包测试覆盖文件清单、SHA-256、厂家日志、配置、应用日志和网络快照，并允许厂家日志尚未产生时导出其余证据。
- Windows 打包测试验证干净机器只启动 `SatelliteDebugTool.exe` 即可创建监听服务，运行目录能够写日志，且重复进入页面不产生第二实例。
- 真机测试依次确认服务监听、驱动连接、低幅单轴动作、MS-6222 实际姿态、停止与重启恢复。软件进程测试不替代物理运动验收。
