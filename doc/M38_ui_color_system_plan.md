## 1. 用户目标与交付范围

用户选择“石墨灰与蓝 · 深色建议”，认可灰阶层次、克制蓝色和独立状态色的方向。
本里程碑将该方向应用到现有 PySide6 界面，统一 Customer、Engineering、Production
及共享弹窗的色彩语义和交互层次。现有页面布局、导航结构、字体尺寸和业务流程继续使用。

交付包含：

1. `dark` 石墨灰深色、`light` 中性灰浅色、`dark_hc` 高对比三主题。
2. 统一的背景、文字、操作、选择、焦点、设备状态和图表颜色角色。
3. 三工作区、共享控件、Shell/摇摆台/电源等弹窗的主题适配。
4. 有效文字和必要图形的对比度验证、实际 Qt 页面视觉复核、功能回归记录。

布局重排、字体系统重建、协议与状态机调整、连接控制、OTA/YMODEM 行为、录制格式、
报告模板、地图瓦片内容与 STL 模型几何由现有合同管理。版本发布与 Git 提交另行按用户指令执行。

## 3. 色彩合同

### 3.1 视觉基准

以下色值用于冻结用户已认可的视觉方向；组件所需完整色阶在实现时按对比度配对补齐。

| 角色 | dark | light | 用途 |
|---|---|---|---|
| 全局背景 | `#18191B` | `#F4F5F7` | 页面底色 |
| 面板 | `#202225` | `#FFFFFF` | 内容承载区域 |
| 次级表面 | `#292C31` | `#F0F1F3` | 输入与次级控件 |
| 正文与主要数值 | `#E8E9EC` | `#25282D` | 标签、SNR、姿态、温度等 |
| 次级文字 | `#ADB1BA` | `#5D636E` | 单位、说明、时间和元数据 |
| 强调前景 | `#85ADFF` | `#245EC7` | 主要操作标识、链接和当前选择标记 |
| 选中背景 | `#2C3442` | `#E9EFFA` | 设备与导航的持续选择 |
| 选中文字 | `#E8E9EC` | `#234F9A` | 选中背景上的文字和图标 |
| 正常状态前景 | `#79C59B` | `#226D43` | 已确认的正常或成功 |
| 告警状态前景 | `#E6B566` | `#88520A` | 需要关注的设备证据 |

强调前景与实底主按钮分别定义配色对。主按钮前景、hover、pressed、focus、disabled
以实际背景上的对比度为验收依据。危险操作与设备故障各有明确的颜色角色及文字。

实现中浅色正常/告警色按最深 hover 表面的文字对比度调深，保留既定色相含义。
进度条拥有专用填充与文字角色，百分比文字在填充区和剩余区均满足可读性要求。

`dark_hc` 保留纯黑背景、纯白主文字与更清晰的控件边界，蓝色表达操作和选择，
绿/橙/红表达设备状态；其配对单独验证。普通深色主题按灰阶逐层提亮建立层次。

### 3.2 使用规则

- **结构**：灰阶承担背景、容器、分隔线和普通按钮；必要面板边框使用中性色。
- **操作**：蓝色集中在主操作、链接、当前选择标记和焦点；次级操作使用中性色。
- **选择**：轻底色与文字、细标记组合；设备选择、导航选择和键盘焦点分别拥有角色。
- **数值**：常规数值与单位通过字号、字重、对齐和正文/次级文字层次建立重点。
- **状态**：正常、告警、故障以现有领域事实为依据；颜色配合明确文字、图标或线型。
- **可用性**：待确认、离线、过期等按既有事实呈现；只有已有告警证据使用告警色。
- **录制**：录制标记表达采集活动，使用独立 recording 角色和明确文字。
- **图表**：多通道保持颜色区分；通道、Roll/Pitch/Yaw、目标/MS/设备姿态、卫星类别映射稳定。
  同一数据类别在主题间允许调整亮度，类别、顺序、图例、线型与来源含义保持一致。
- **终端**：ANSI 色号表达设备输出的协议含义；终端底色、普通文字、时间戳和输入控件按主题适配。
  ANSI 调整限于保证各主题下可读的映射，保留 SGR/复位语义。

### 3.3 单一颜色来源

`ui/styles.py` 是应用主题与集中图表角色的颜色 owner，`ui/qss.py` 和组件消费这些角色。
新增 selected/focus/status/recording/chart 等语义角色必须与现有 API 的有效调用关系一起整理。
现有 `palette()`、主题 ID、bool 调用和设置值继续履行当前合同；历史常量按现有调用需求
从同一色板导出。被替代的局部状态色表和装饰样式随迁移删除。

Qt 透明色在实际父表面上合成，QSS 颜色使用 Qt 支持的格式；转换由统一入口负责。
控件刷新沿用 `semantic_style` 的幂等刷新方式，颜色更新由主题切换或语义属性变化驱动。

## 5. 实施顺序

1. **P0 计划确认**：确认本文与验收标准；记录用户确认后进入 P1。
2. **P1 角色与色板**：补齐角色和配对，更新全局 QSS，建立三主题对比度回归。
3. **P2 共享 chrome 与 Customer**：统一选中/焦点/状态/数值，审查实际子控件背景。
4. **P3 Engineering 与图表**：收敛状态色表，适配类别色、图例和主题刷新。
5. **P4 Production 与共享弹窗**：覆盖夹具、批次和 Shell；检查已构建及懒加载页面。
6. **P5 验证与交付**：执行针对性与全量回归、翻译检查、Qt 视觉复核；逐项更新验收结果与开发记录。

每个阶段记录涉及文件、实际证据、发现的问题和相对计划的范围变化。

## 6. 验证与完成标准

- 普通有效文字在实际背景上的对比度 ≥ 4.5:1；大字 ≥ 3:1；必要图形和焦点指示 ≥ 3:1。
  `dark_hc` 主文字目标 ≥ 7:1，次级有效文字 ≥ 4.5:1。纯装饰边线与禁用控件单独记录用途。
- 先加入能在旧实现稳定复现颜色配对、状态映射或主题刷新问题的针对性回归，再验证新实现。
  测试验证行为与可读性合同，不绑定全部 HEX 值作为快照。
- 使用现有 pytest QApplication、offscreen 与静默更新 fixture，运行受影响测试和全量测试。
- 执行 `python3 scripts/update_translations.py check`；文案变化时先 update，再 check 并交付 TS/QM。
- Qt 截图覆盖 1440×900 与 1280×800；记录实际最小尺寸、缩放、三主题和中英文关键页面。
- macOS 实际 Qt 视窗复核 3D/OpenGL、图表、焦点和弹窗；Windows 实际检查状态独立记录。
  offscreen 截图证明相应离屏呈现，3D/OpenGL 和现场屏幕效果由真实平台证据确认。
- `git diff --check` 通过；对照页面覆盖清单、验收标准和旧颜色引用完成 review。

完成时报告代码/自动化验证、实际平台视觉结果与待验项目。界面配色证据对应软件呈现；
设备在线、升级生效、RF 与夹具精度继续使用各自已有验收证据。
