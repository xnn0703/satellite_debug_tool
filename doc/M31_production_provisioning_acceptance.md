# M31 出货固件、参数基线与最终 IP 自动整备验收标准

## A. 配置包

- [ ] ProvisioningBundle 包含 AES-GCM 加密固件、参数基线、网络配置和完整 manifest。
- [ ] 导入校验 schema、产品、硬件范围、全部 SHA-256 和固件认证解密后再原子提交。
- [ ] 产品模板冻结 bundle ID、revision 和文件哈希，源文件变化不改变已创建批次。
- [ ] 配置包支持导出并在另一工作站完整导入。

## B. 参数所有权与比较

- [ ] 每个可见参数属于 `managed`、`identity`、`network_runtime`、`network_shipping`、`device_specific` 或 `observed`。
- [ ] 只有 `managed` 参数可由通用基线自动写入。
- [ ] SN、MAC 和硬件 UID只作为身份显示，不进入差异或写命令。
- [ ] 浮点、枚举、整数、布尔、字符串和网络值按各自规则比较。
- [ ] 未知字段、重复字段、类型变化和缺少必需字段明确失败。
- [ ] 差异预览准确显示当前值、目标值、写入顺序和重启要求。

## C. 固件整备

- [ ] 当前版本匹配时不发送 OTA。
- [ ] 版本不一致时只使用与当前产品和硬件匹配且已认证解密的固件包。
- [ ] OTA 完成后同一硬件 UID重新上线，身份事实与升级前一致。
- [ ] 所有固件来源一致并匹配目标版本后才进入参数整备。
- [ ] OTA 拒绝、超时、返回身份变化或版本未确认时设备进入 `provisioning_failed`。

## D. 参数整备

- [ ] 固件确认后读取当前连接代际的完整参数表。
- [ ] 已匹配参数不写入，只对差异项按依赖顺序执行。
- [ ] 每项写入同时具有匹配 ACK 和参数表读回证据。
- [ ] 全部写入后再次读取完整表并确认全部受管字段。
- [ ] 设备拒绝、断线、读回不符或重启后丢失时不进入正式工况。

## E. 临时 IP 与 endpoint 迁移

- [ ] 同批设备测试期间使用唯一 endpoint，额外设备或冲突设备阻止启动。
- [ ] 改临时 IP 前冻结硬件 UID、SN 和 MAC。
- [ ] 新 endpoint 只有在硬件 UID、SN 和 MAC 一致后才归属原设备。
- [ ] 网络参数不可写或产品能力未知时进入明确人工门禁。
- [ ] 未确认迁移时不把新 endpoint 的数据写入原 attempt。

## F. 最终出货 IP

- [ ] 最终网络配置只在所有网络测试和证据冻结后执行。
- [ ] 相同出货 IP 的多台设备按槽位逐台隔离、写入、重连、确认和断开。
- [ ] 最终重连确认同一硬件 UID、SN、MAC 和网络读回。
- [ ] 任一设备最终网络验证失败时保持 `INCOMPLETE`，其他设备结果独立。
- [ ] 报告记录测试 endpoint、目标出货配置和最终确认结果。

## G. 所有权与恢复

- [ ] 每台设备只有一个 `DeviceProvisioningCoordinator` 拥有 OTA、参数和网络整备状态。
- [ ] OTA 与参数写入复用 Runtime 事务网关，不存在页面旁路写入。
- [ ] 应用退出、人工中止和批次异常等待当前设备操作得到确定终态。
- [ ] 失败保留已确认步骤、原始快照和错误证据，不自动盲目回滚或继续。
- [ ] 重启软件后能读取冻结证据，未确认操作保持失败或待人工复核。

## H. 自动化测试

- [ ] 已匹配、不匹配、OTA 成功、OTA 失败和返回身份变化均有状态机回归。
- [ ] 参数无差异、多项差异、类型错误、ACK 拒绝、读回不符和中途断线均有回归。
- [ ] endpoint 迁移成功、身份不符、重复 IP 和多台同出货 IP顺序流程均有回归。
- [ ] 一台和两台设备的报告、证据 ZIP 与 manifest 哈希正确。
- [ ] 翻译检查、`compileall`、`git diff --check` 和全量 pytest 通过。

## I. 真机验收

- [ ] 用一台真实 DUT 从旧固件和偏差参数自动整备到出货状态并完成正式工况。
- [ ] 用两台真实 DUT 在唯一临时 IP 下完成整备与测试。
- [ ] 两台设备最终写入相同出货 IP时，逐台隔离确认且无错误归属。
- [ ] 断网、掉电、设备拒绝和重启超时均产生可复核失败证据。
- [ ] Windows 打包版能够导入配置包并完成整备，无开发环境依赖。
