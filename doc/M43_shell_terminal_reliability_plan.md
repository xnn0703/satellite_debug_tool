# M43 Shell 输入与终端回显可靠性计划

日期：2026-10-27。用户已确认“单次解码、终端编辑模型、输入防误操作”三项修复范围；本计划将已确认范围具体化。交付方式为源码修复、回归证据与两版运行指令，现场功能验证后按用户后续指令打包。

## 1. 事实与根因

- 会话 `20261026T124831Z-61d7ca65` 的 TX 证明首次输入包含 UTF-8 `——`，设备 Letter Shell 按字节退格，历史回显保留 `E2 80 94 E2`；第二次在历史命令上修改，按设备字节编辑重放得到 `para extt_ins_rot 4`。后续 ASCII 命令成功，参数两次读回为 4。
- `TcpShellWorkspace._on_rx_payload()` 对每批数据调用同一增量解码器两次；UTF-8 和 ANSI 跨包状态因此失真。分包 `E2` / `80 94` 已稳定复现显示替换字符。
- 现有 QTextEdit 呈现把 BS 当删除字符，并在每包起点将游标移到文档末尾；部分 ANSI 光标序列被丢弃，编辑呈现与终端语义不同。
- 键盘和粘贴直接编码 UTF-8，普通命令入口缺少明确字符合同。输入法提交需纳入同一入口。

## 2. 权威 owner 与实现范围

1. `core/tcp_shell/terminal.py` 提供纯 Python 流式解码、ASCII 命令文本校验和终端行/光标模型。解码每批只执行一次，tokens 同时供可读日志与呈现消费；原始字节事实继续由 recorder 持有。
2. 终端模型拥有行内容、单元格、光标和 SGR 状态；Qt 文档只投影模型。支持本项目行交互所需的 CR、LF、BS、TAB、SGR、EL 与水平光标控制，覆盖用户历史编辑、固件日志重绘和 OTA 进度条。
3. BS 移动光标；后续字符覆盖已有单元格。横向游标跨接收包保持，时间戳属于呈现前缀。UTF-8 异常输出可见替换标记和提示，解码控制序列使用有界缓冲。
4. 普通命令文本采用 ASCII 合同：键盘文字、输入法 commit、粘贴共用校验；非 ASCII 或粘贴中的特殊控制字节整次拒绝并提示代码点，用户切换英文/ABC 后重输。ASCII `_` 原样发送；设备控制键按既有映射发送。接收 UTF-8 日志继续正常显示。
5. 正文/HEX 是同一接收流的两种呈现；正文模型持续消费接收 tokens，切换 HEX 保持正文解析与光标状态。用户/运维共用实现。
6. YMODEM、原始传输、设备固件及参数配置 owner 保持各自合同。该修复不把可读终端文本当作设备参数回读或持久化事实。

## 3. 工作顺序

- 建立脱敏会话 fixture（只保留参数失败窗口 TX/RX；登录凭据及设备参数列表排除），先验证旧实现的失败测试。
- 实现单次解码、终端模型与输入校验；删除被替代的正则解析、按文档删除 BS、包尾游标复位及重复状态分支。
- 回归 TCP/串口共享入口、HEX/正文切换、日志、时间戳、主题、清屏与关闭；更新共享包模块合同和翻译。
- 按验收标准逐项核对，执行 Shell 专项和全量 pytest，更新开发记录与 AGENTS.md，提供源码运行指令。

## 4. 验证与现场边界

软件验证使用真实会话脱敏字节、逐切点/逐字节分包与 UI 回归。普通终端属于有界行交互范围，完整 xterm 全屏应用另立需求。macOS/Windows 原生输入法事件与真实 TCP/串口设备交互需现场验证；现场参数持久化以设备回读和重启证据确认。
