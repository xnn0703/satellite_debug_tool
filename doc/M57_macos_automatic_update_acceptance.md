# M57 macOS 运维版自动更新验收标准

日期：2026-11-03。状态：软件实现与自动化回归完成；A12 真实双版本升级/故障恢复待下一个唯一冻结版本执行。

| ID | 验收要求 |
| --- | --- |
| A01 | macOS ops 可信目录声明 `installation_mode=automatic`，同时包含完整包、`macos-app-v1` 树清单；user 目录保持人工完整包。 |
| A02 | 下载完成后显示“安装并重启”；一次确认后由主窗口完成资源收尾，界面不再要求打开目录人工替换。 |
| A03 | 退出旧程序前完成 TUF、包 SHA-256、树清单、磁盘空间、父目录写权限、唯一 `.app`、bundle id、版本、edition、架构、build ID 和 codesign 验证。任一失败保持旧程序运行、旧 app 不变。 |
| A04 | updater 的持久副本位于旧 `.app` 外，旧主程序与其子进程全部退出后才允许切换。更新器不能从被替换目录加载运行时依赖。 |
| A05 | staging 与正式 `.app` 位于同一文件系统；journal 和恢复入口先落盘，之后只用同盘 rename 切换，禁止文件级叠加覆盖旧 app。 |
| A06 | 新 app 自动启动并返回绑定 transaction/version/PID 的健康回执；提交后显示新版本，配置、录制路径和已有数据保持。 |
| A07 | 新版启动异常、健康超时、候选签名错误、切换中断和进程残留均恢复旧 app；旧版可重新启动，journal、状态和日志保留可诊断事实。 |
| A08 | LaunchAgent 恢复入口只引用事务目录中的受验证 updater/journal；成功或已恢复终态删除，重复触发保持幂等。 |
| A09 | 当前用户无安装父目录写权限时，在旧程序退出前明确停止；不静默提权，不改变目录权限，不留下半安装状态。 |
| A10 | Windows ops 自动安装、user 人工交付、TUF 最后提交、服务器 SHA 复核、设备固件 OTA 与现有业务资源收尾合同无回归。 |
| A11 | 自动化覆盖完整成功链、摘要/身份/签名失败、权限失败、主程序不退出、交换各阶段故障、健康失败回滚、恢复幂等、user 拒绝和 Windows 回归。 |
| A12 | 在本机用两个真实冻结 macOS ops 版本完成至少一次升级成功和一次人为健康失败自动恢复；记录 `.app` 版本、签名、PID、journal、健康回执及配置保留证据。 |
| A13 | 全量 pytest、翻译 update/check、compileall、冻结 smoke、归档 CRC/身份、`git diff --check` 通过；Apple notarization 和其他 Mac 架构未实测时明确记录为未验收。 |

## 当前验收结论

- A01-A11：源码、真实 v1.9.1 归档检查和自动化事务回归已覆盖并通过。
- A12：待下一个唯一版本冻结后执行，当前不得宣称真实跨版本现场验收完成。
- A13：2256 项全量测试、最终 53 项 updater 专项、1502 条翻译检查、compileall、差异检查通过；实际 v1.9.1 Mac ops 归档的文件树、身份、签名和外置 updater 已复核。Apple notarization 与 x86_64 未验收。
- 首个包含 M57 的版本仍需要 v1.9.0/v1.9.1 用户完成一次人工替换；之后的 macOS ops 更新才具备真正的“安装并重启”。

## 不等价结论

- TUF、SHA-256、codesign 和软件回归通过，不等于 Apple Developer ID 公证完成。
- 本机 arm64 自动升级通过，不等于 x86_64 或所有 macOS 版本通过。
- 应用升级成功不证明设备连接、RF、供电、摇摆台或生产测试结果。
