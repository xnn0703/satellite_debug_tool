# M19-A.3 PSW 开启流程与升压确认修复计划

## 现场证据

会话 `20260918T110227Z-bce6821e` 已证明两项事实：

1. 当前“开启输出”按钮只在 adapter 状态为 `READY_OFF` 时启用，因此操作者必须先点击“准备输出关闭”。该按钮实际执行输出关闭、电压/电流写入、设定值读回、错误队列和保护状态检查，现有文案没有表达完整含义。
2. 第二次 `OUTPUT ON` 在约 70 ms 后读取到 `-0.003 V` 并立即判定失败；约 1.52 s 后的首次状态读取为 `12.005 V`，已经进入配置的 `11..13 V` 窗口。当前实现把异步升压过程错误建模为一次立即读回。

## 修复目标

- 保留 `READY_OFF` 作为核心安全前置状态，不删除 OFF、设定值和保护检查。
- 操作者点击一次“开启输出”即可完成内部 `READY_OFF` 准备和 OUTPUT ON 闭环，不再要求先手工点击准备按钮。
- OUTPUT ON 后在明确的稳定期限内观察输出、实测电压和保护状态；只有电压进入窗口且保护正常时确认开启成功。
- 超过期限仍未进入窗口时报告最后实测值和稳定超时，不把正常升压中的单次低电压立即判为失败。

## 最小实现

### 1. 单次开启操作

- “开启输出”在身份已验证、输出已确认关闭或 `READY_OFF` 时可用。
- worker 收到一次开启意图后：
  1. 若尚未处于 `READY_OFF`，先调用现有 `prepare_output_off()`；
  2. 再调用现有 `enable_output()`；
  3. 两段使用同一个 action ID，保持一条可追踪操作链。
- “准备输出关闭”保留为独立诊断入口，文案改为“应用参数并确认关闭”，准确说明它包含写设定值。
- 开启确认框明确显示：本操作会先关闭输出、应用设定值，然后开启并等待电压稳定。

### 2. 升压稳定合同

- `PowerSupplyConfig` 新增显式的输出稳定超时，电源页显示“输出稳定超时 (s)”，默认 3 s。
- `enable_output()` 发送 `OUTP 1` 后保持 `TURNING_ON`，在稳定期限内按固定短间隔执行闭环观测：
  - `OUTP?`
  - `MEAS:ALL?`
  - `STAT:OPER:COND?`
  - `STAT:QUES:COND?`
  - `OUTP:PROT:TRIP?`
- 输出关闭、保护触发或告警状态立即失败；输出已开启但电压尚未进入窗口时继续等待。
- 电压进入窗口后进入 `ON_CONFIRMED / VOLTAGE_CONFIRMED`。
- 稳定期限结束仍未进入窗口时进入 `UNKNOWN`，错误包含最后电压与配置窗口。

### 3. 证据与生命周期

- 每次稳定观测均继续写入现有 SCPI 记录，保留同一 action ID。
- UI 在整个复合操作期间保持 busy，只允许“关闭输出”排队为优先安全意图。
- 断线、查询失败和关闭应用继续使用现有 worker/transport 收尾合同。

### 4. 自动验证限制

- 操作者只输入需求电压和电流；设定值读回容差、OUTPUT ON 窗口和 OUTPUT OFF 门限由 PSW80-27 验证策略计算并只读显示。
- OUTPUT ON 窗口按官方电压设定精度、测量精度和远程分辨率合成；12 V 对应 `11.952..12.048 V`。
- OUTPUT OFF 门限固定为 `0.050 V`。关闭和 OFF 准备在稳定期限内等待电压下降，避免用旧的宽松手工门限把放电过程误判为已经关闭。

## 回归验证

- 新增现场故障回归：第一次测量低于窗口，后续测量达到 12 V，开启操作最终通过。
- 新增稳定超时回归：持续低电压，到期后以最后电压失败并进入 `UNKNOWN`。
- 新增保护触发、输出回落和通信失败回归，证明不会把异常升压确认成功。
- UI 回归覆盖：连接识别后“开启输出”可用；单击一次自动执行 OFF 准备和 ON；`READY_OFF` 时不重复准备。
- 更新中英文翻译，运行电源专项、Production Workspace 相关测试和全量 pytest。

## 不改变的边界

- 不自动重试 `OUTP 1`，一个开启意图只发送一次 OUTPUT ON。
- 不清除 OVP/OCP，不绕过保护或告警状态。
- 不把命令发送或 `OUTP?=1` 单独解释为电压已确认。
- 不接入批次自动测试和正式试产报告。
