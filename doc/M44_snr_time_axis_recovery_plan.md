# M44 客户 SNR 与设备时间轴恢复计划

日期：2026-10-28。用户回复“可以”确认本计划，进入源码修复与验收。保留 M43 工作区改动；本轮提供源码运行方式，打包依据后续明确指令执行。

## 1. 已确认事实

1. `CustomerOverviewView._refresh_snr()` 每次刷新会根据历史有限数值设置 Y 范围；数值读数来自 snapshot，曲线与坐标范围来自历史，两者可能分离。
2. `ProductServiceStore.feed(ServiceFastState)` 先更新 `_fast`，再通过 `_snr_timestamp.add()` 判定历史样本。设备 uptime 由 600000 ms 回到 1000 ms 时，当前读数更新为 18.5，而历史仍为 `(600 s, 0 dB)`。
3. `U32UptimeUnwrapper` 将 u32 半区规则内的反向时间判为旧包，正确保护了乱序场景；同连接设备时间线重新开始缺少 owner 驱动的 epoch 处理。
4. `DeviceSessionCore.apply_records()` 接收新的同设备身份和低 uptime 心跳，当前流程仍直接更新 Store。`EndpointSessionRuntime` 的 presence epoch 仅更新身份授权事实，恢复 presence 时没有同步恢复历史时间锚点。
5. `clear_history()` 只清显示样本，按原合同保留时间锚点。重启后单独清样本会继续拒收低 uptime 样本。该按钮合同与“新启动代际”是不同事实，应分别处理。
6. Debug v2 的 `LegacyV2Projector.channel_history()` 从混合新旧启动数据重新展开时间，也会跳过重启后低 uptime 数据；模块温度历史使用独立的同类 unwrapper，同样复现停更。
7. 旧历史全 NaN、旧 Y 窗口为 `[-1,1]` 时，重启后新读数为 18.5，曲线仍全 NaN，Y 窗口保持原值。正常前进时间样本的 Y 轴更新控制实验通过。

## 2. 修复方向与 owner

- 会话层在样本进入 Store 之前统一管理设备采集时间代际；Product Service、Debug v2 与温度等历史消费同一代际事实。显式重连、确认的接收连续性中断、同连接设备时间线重新开始分别定义证据与处理顺序。
- u32 自然回绕保持连续；单个旧包保持拒收。物理重启与采集流重建使用各自事实文案。现协议时间戳、心跳和固定身份本身缺少唯一 boot ID；物理重启不能仅由单帧反向时间确定。实施前需冻结“新时间段候选/确认/迟到旧段包”的合同与专项用例。
- 确认新采集代际后，统一处理相关历史及时间锚点，旧段与新段分开；保持 endpoint 绑定、录制事实、profile 定义及事务所有权边界。新代际需要明确触发事务 readback 基线的失效/重建规则。
- 数值、历史、X/Y 范围依据同一来源和代际；有效有限值到达后进入当前五分钟窗口。无有效样本时呈现明确状态，NaN/Inf 保持断点语义。
- 清空显示维持本地显示动作合同；设备时间段恢复由会话 owner 驱动，避免在刷新或按钮路径中维护第二份启动状态。
- 用户/运维共用修复，Customer/Engineering 的共享 endpoint Runtime 与离线回放分别验收。

## 4. 已冻结的采集时间合同

- `DeviceSessionCore` 使用 `TelemetryClock` 在 Store 入库前准入。每种报告保留单独的 u32 高水位；不同频率的报告允许自然交错。同一周期流（Fast、Data、Heartbeat、ComponentHealth）的三个严格推进的反向时间样本确认一个新采集段。重复值不增加证据，当前流恢复原高水位时撤销该流候选。
- 候选缓存上限 256 帧、5 秒。身份/控制响应自身不能确认新段；这些记录遵循各自类型的入库时间规则。确认前保留原段当前值和曲线；确认时统一清理动态事实及历史锚点，再按原接收时间回放候选。
- 带主机接收时间时，u32 数值下降所对应的自然回绕跨度需要与实际经过时间一致（允许 2000 ms 传输抖动）。该规则区分 24.9 天以上 uptime 归零与短跨度自然回绕。
- 新段建立后，移动的时间围栏按主机经过时间和 2000 ms 抖动约束后续前向跨度；迟到的旧高 uptime 包留在原始证据，当前 Store 保持新段事实。围栏随有效进度更新，持续运行到半区与自然回绕后仍可继续采集。
- `ProductServiceStore.telemetry_epoch` 是采集代际事实；连接 generation 与 endpoint 保持原值，传输 capability 继续有效。`DeviceSessionScope` 纳入 telemetry epoch，旧操作 scope 失效。参数/普通控制结束为会话变化；OTA 或安装标定已经进入等待重启阶段时继续原有身份和回读验证。Runtime 新建 presence epoch，重新取得身份授权。
- 显式重新连接清理动态 Store 和时间准入状态；显示清空继续保留协议时间锚点。Product 静态身份/profile 定义保留为已知事实，动态应用结论依赖新段回读。
- SDB 原始帧保留全部证据，派生回放复用准入模型，将确认的新段映射到连续显示轴并插入 NaN 断点；夹具相关性显式分段。SDB v2 没有逐帧主机时间，使用 u32 半区和连续样本合同；其长 uptime 回绕/归零的不可辨识边界保留。
- 当前协议缺少 boot ID。上述证据确认“新的采集时间段”；连续重放的旧数据流、短于时间分辨能力的归零与物理重启之间仍存在协议辨识边界。现场验收与协议升级分别记录。
