# M19-A.6 单设备自动报告与证据归档计划

## 目标

- 每台参与设备以冻结的批次结果生成独立中文 DOCX 与自包含证据 ZIP。
- 完成状态生成不可覆盖的 V1；审核生成 V2 并保留自动结论、审核人、时间和原因。
- 中止或不完整批次只归档证据，不生成正式报告。
- 报告目录按日期、型号、SN、批次号组织，所有产物由 SHA-256 manifest 追溯。

## 实现边界

- `ProductionResultStore` 升级并保存冻结快照、报告产物和审核记录。
- 新增报告领域服务，负责路径、证据 ZIP、DOCX、manifest 和 V2 审核。
- `BatchCoordinator` 增加肯定式完成入口；`ProductionWorkspace` 在录制结束后调用报告服务。
- 报告品牌信息由设置与工作站配置提供，批次创建时冻结。
- DOCX 仅依赖项目 Python 运行环境，不依赖 Microsoft Word。

## 交付规则

- PASS/FAIL 是设备级自动结论；存在 FAIL 即 FAIL，其余已完成或 N/A 时为 PASS。
- INCOMPLETE/ABORTED 不允许审核为 PASS。
- 同一报告版本不可覆盖；V2 只能从已生成的 V1 和一次不可变审核记录生成。
- 缺失的硬件证据以明确的 unavailable 元数据表示，不伪造测量值。

## 过程曲线与分析补充

- 从设备 SDB 的主机接收时间轴提取 SNR、roll、pitch、yaw；Product Service 数据存在时作为单一优先来源，旧 Debug 通道仅在 Product Service 缺失时按 Profile 语义回退。
- 使用事件表中的 UTC/单调时钟对应关系，把 attempt 时间窗换算到 SDB 主机 UTC 时间轴；每个测试项形成独立阶段窗口，不用最终 phase 字段推测不存在的子阶段。
- 报告至少包含全程 SNR 曲线、全程姿态曲线、SNR 趋势/稳定性统计和各测试项阶段结论。MS6222 有有效标定和同期样本时再增加姿态误差与收敛/发散分析。
- 趋势分析保存样本数、覆盖时长、起始/末尾稳健中位数、变化量、线性斜率、均值、标准差、最小值和最大值；阈值仅从配方或已记录指标取得。
- 未配置判定阈值时只陈述可复算的趋势事实并标记“待判定”；没有外部参考时不把设备姿态变化解释成跟踪误差。
- 分析数据和图像随冻结快照固化，并写入 evidence.zip，保证 V1/V2 使用同一分析输入。

## 工况报告结构

- 报告把设备检查、测试工况和跨工况汇总分开呈现，测试工况是曲线分析和结论的主单位。
- 一级工况固定为：静态、锁定后摇摆、摇摆中上电、车载动态。
- 车载动态保留两个独立子场景：锁定后车载、车载中上电；两者各自保留 attempt 时间窗和结论，并在车载动态章节汇总。
- 每个启用工况都生成本时间窗内的 SNR/锁定状态、设备姿态和可用的 MS6222 姿态误差曲线，不复用全程图代替工况图。
- 每个工况显示输入条件、执行次数、数据覆盖、统计指标、异常、子场景结论和工况总结；未启用工况显示“未启用”，已启用但没有有效时间窗或曲线时显示具体数据缺口。
- GNSS、IMU、外部 INS 和整机导航属于跨工况指标汇总，引用对应工况窗口，但不作为与四个工况并列的运行场景。

## 封面与测试环境

- 封面采用正式检验报告版式：右上报告编号与分隔线、居中“测试报告”主标题、产品名称/型号/编号及批次和版本信息、编写/审核/批准签署表、底部成文日期。
- PASS/FAIL 作为产品信息中的正式字段呈现，不再作为封面中央的大号视觉元素；自动结论和审核后的最终结论继续分别保留。
- 产品名称优先取批次冻结的产品模板名称，产品型号取设备身份或配方型号，产品编号取设备 SN。
- 正文“设备与测试配置”增加独立“测试环境”小节，冻结并显示测试地点、工位、工作站、操作系统、软件版本、时区、设备网络端点、电源连接、摇摆台配置、MS6222 配置以及环境温湿度。
- 可由软件自动确定的环境事实自动写入；地点、温度、湿度等未配置或未采集的信息明确显示“未配置”或“未记录”，不得补造。
