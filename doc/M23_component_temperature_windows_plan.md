# M23 部件温度曲线悬浮窗计划

状态：实现与定向软件验收完成；实机、窗口管理器与发布包验证待执行

验收标准：`doc/M23_component_temperature_windows_acceptance.md`

开发记录：`doc/M23_component_temperature_windows_dev_log.md`

## 1. 已核对基线

- 当前 Customer Overview 已从 Product Service `0x23 COMPONENT_HEALTH` 显示变频器、TX 阵列和 RX 阵列的在线状态、温度、电压与版本。
- `ProductServiceStore` 是 Product 遥测的权威状态源；界面不得另建协议接收路径，也不得因打开曲线窗向设备发送查询。
- ESA01 使用已注册的 Product Service protocol 6；AFD01/AFD01C 继续使用各自已注册协议。`0x23` 的三部件固定记录合同不变。
- 当前工作区已有未提交的 M22/Customer Overview 改动，本轮必须保留，不覆盖或回退。

## 2. 目标

1. 点击底部“变频器”“TX 阵列”“RX 阵列”状态项时，打开对应部件的独立温度历史曲线窗。
2. 三个窗口可同时显示；再次点击已打开的部件时激活原窗口，不创建重复窗口。
3. 窗口初始悬浮在对应状态项附近，并支持操作系统原生的最大化、最小化和关闭。
4. 曲线只消费当前连接中 `ProductServiceStore` 已接收的有效温度记录；断线或会话清理时同步清空，不把旧设备数据带入新会话。

## 3. 数据与交互合同

- 在 `ProductServiceStore` 内为三部件维护有界温度历史，设备 uptime 作为横轴；重复、回绕和乱序规则复用 Product 时间戳处理方式。
- 只有 `temperature` valid bit 有效且数值有限时才作为温度点；字段无效时保留缺口，不伪造 `0 °C`。
- 历史属于当前连接的内存数据，不写磁盘；`clear()` 与连接代际切换共同清空。
- 弹窗只负责呈现 Store 历史和当前字段状态；不拥有第二份业务状态，不发送 Product SUBSCRIBE、KA256 INFO 或其他设备命令。
- 关闭窗口只关闭呈现；再次点击可重新打开。最大化、最小化和关闭均使用标准顶层窗口能力。

## 4. 本轮边界

- 包含：三部件温度历史、独立窗口、锚点定位、主题与语言切换、定向回归测试。
- 不包含：落盘/导出、跨连接历史、告警阈值、缩放区间配置、协议扩展、固件额外轮询、安装包发布。
- 按用户要求不执行全量回归；只运行相关 Store、Customer Overview、翻译检查和差异检查。

## 5. 完成定义

- 三个部件状态项都可打开自己的温度曲线窗，且三窗可同时存在。
- 窗口靠近被点击状态项出现，重复点击复用并激活现有窗口，标准窗口控制可用。
- 有效温度形成曲线，无效温度不显示成真实零值，断线后历史清空。
- 原有姿态、波束、SNR 和三部件即时状态显示保持不变。
- 定向 pytest、翻译检查与 `git diff --check` 通过；真机连续温升曲线和发布包平台行为明确保留为待验证。
