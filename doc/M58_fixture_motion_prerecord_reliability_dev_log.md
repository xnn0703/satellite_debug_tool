## 实施记录

### 连续运动时间线

- 夹具姿态图改为每个数据源固定 2,400 点投影预算，五分钟窗口内的单次 UI 工作量不再随样本累计增长。
- `TrajectoryResult` 新增实际发送间隔最大值、P95、P99、控制空洞、命令完成时间和 `timing_fault`。
- 连续发送资格与单次动作最短时间分离：当前软件资格周期为 50 ms，20 ms 保持待现场验证。
- 客户/工程摇摆台界面的采样周期下限同步固定为 50 ms，未资格确认的 10..49 ms 不再作为可选输入。
- 指令完成时间采用采样周期的 1.2 倍覆盖窗口；实际间隔超过该窗口时保存控制空洞。M60现场复测后，完整调度槽迟到改为保存 timing fault、继续当前点并重建周期，不再停止后续轨迹点。

### 2026-11-03 50 ms 首轮现场复测修正

- 会话 `20261103T070327-3695bcc3` 三次轨迹分别在软件记录的 61.30 / 83.39 / 64.17 ms 后被主动终止，只发送 22 / 134 / 398 点。
- `ttt.pcapng` 对应线上最大间隔为 59.27 / 57.01 / 64.09 ms；第二次 83.39 ms 是轨迹循环入口时间，不是 UDP 发出时间。
- 控制器反馈共 32,527 帧，最大间隔 21.357 ms；没有控制器反馈停顿证据。
- 发送间隔事实改为消费 `MotionCommandEvent.monotonic_ns`。超过 60 ms 记录控制空洞；完整 50 ms 调度槽迟到形成 timing fault。M60证明终止策略会造成更长保持，现行实现记录后继续且不追赶突发。
- 现场修正后扩大影响面回归：85 passed。单进程全量两次分别被外部 SIGTERM/SIGKILL 中止且中止前无断言失败；为释放 GUI 测试累计内存，按相同文件全集分四个独立 pytest 进程执行，结果为 511 + 673 + 469 + 606 = 2,259 passed。

### 三轴组合包线

- 新增不可变 `TrajectoryPreflightResult`；UI 预览和 worker 执行复用同一轨迹及摘要。
- 包线以 20 ms 路径分辨率执行严格六缸逆解，避免 50 ms 指令点漏过插值路径中的极值。
- 14°现场参数回归得到 axis 4 最小伸长量 0.51 mm；15°在预览阶段复现 axis 4 `-0.21 mm` 和限制姿态。
- 未增加逐缸钳位、自动缩放或设备特例。

### 预录制

- 客户录制租约从 `support_full` 控制器拆出，改为 endpoint Runtime 的 `CUSTOMER_RECORDING` owner。
- 点击预录制立即创建 SDB v3；`WAITING_DEVICE / NEGOTIATING_FULL / FULL / PASSIVE / RESTORING` 成为独立采集阶段。
- 完整采集发送失败、超时、拒绝或能力不支持只把阶段置为 `PASSIVE`，不再关闭 recorder。
- 采集阶段作为 metadata 写入同一 SDB；summary 独立保存原始写入完整性、最终阶段和 `support_full` 覆盖区间。
- 应用退出显式释放已确认完整采集所保留的 mutation owner，避免 Runtime recorder/operation 泄漏。
