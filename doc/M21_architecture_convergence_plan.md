# M21 单进程架构收敛与长时运行治理计划

## 目标

保持一个完整可执行程序和现有快捷键入口，将客户、工程、试产三套工作区收敛到共享会话、按需呈现的运行模型。通信、握手、录制、OTA、批次执行和夹具采集按业务状态持续运行；曲线、3D、表格与页面刷新只在对应页面可见时运行。

本里程碑同时治理长时回放、夹具证据链、产品字段来源、协议模块边界和试产协调职责，使后续客户功能、工程诊断和批量测试建立在同一套权威状态源上。

## 实施范围

### 1. 工作区与页面生命周期

- 所有工作区和高频页面统一提供 `activate_view()` / `deactivate_view()` 生命周期。
- `MainWindow` 是顶层工作区生命周期的唯一调度者；Customer、Engineering、Production 各自只调度当前子页面。
- 隐藏页面停止曲线重绘、3D 刷新、表格扫描和夹具绘图；设备通信、握手、录制、OTA、批次状态机和 MS-6222 采集继续运行。
- 页面激活后先执行一次即时刷新，再启动可见刷新定时器；全部定时器绑定 QObject 父对象并在销毁时停止。
- STL 网格采用进程级只读缓存，多个视图共享解析结果。

### 2. 页面按需构建

- 默认只构建客户总览和共享设备会话。
- 客户射频、客户回放、维护、工程 Tab 和试产工作区在首次访问时构建，构建完成后保留实例。
- 按需构建不改变快捷键、当前连接、Store、录制状态和设备事务。
- 页面首次构建与后续切换分别记录耗时，便于持续监控体验回归。

### 3. 统一设备会话与控制器

- 从 `LiveView`、`DeviceView` 和试产 Fleet 中抽取 `DeviceSessionCore` 与 `SessionRegistry`。
- 会话内核统一拥有 worker、组帧器、Handshake、Profile、遥测 Store、产品服务订阅、录制入口和连接代际。
- Debug、参数、OTA、产品控制分别进入控制器；界面只发出操作意图并订阅类型化状态。
- 单设备客户/工程视图和多设备试产视图复用同一会话合同；一个 endpoint 在同一进程中只存在一个权威会话。
- 遥测历史统一为可查询的 `TelemetrySeriesStore`，实时曲线、录制和回放使用同一时间与缺口语义。

### 4. 产品字段来源状态机

- 产品字段可用性扩展为 `PENDING / VALID / STALE / UNSUPPORTED`。
- 每个值携带来源、采样时间、新鲜度和质量；界面不再根据字段名或设备型号猜测来源。
- 在线连接在发现窗口内等待 Product Service；确认支持后整帧使用产品源，确认旧合同后整帧使用 legacy 投影。
- 同一快照不混合两个来源。回放文件包含产品记录时使用产品投影，否则使用 legacy 投影。
- 未确认能力显示“待确认”，明确不支持显示“不支持”。

### 5. 协议实现拆分

- 保持 DEBUG v2、Product Service、Orbit 的线上字节合同和公开 import 兼容。
- 按领域拆分模型、编码器、解码器和命令注册表；`core.protocol` 继续提供兼容重导出。
- `FrameReceiverV2` 只负责包络、CRC、恢复和领域解码分发。
- 每个领域拥有 golden vector，验证拆分前后编码字节与解码模型完全一致。

### 6. SDB、回放与长时证据

- Recorder 与 Importer 共用 SDB schema 定义。
- `DataImporter` 改为流式读取，并为大型 SDB 生成可重建的稀疏 `.sdbi` 索引。
- 回放解析和查询在后台线程执行，UI 通过 `PlaybackSeriesProvider` 获取窗口数据，不在主线程读取整文件。
- 实时和回放曲线按像素预算抽样，缩放后再请求对应时间窗口。
- 夹具显示保留最近 5 分钟；完整原始数据持续写盘并在线累计指标。
- 夹具写入队列有明确容量和溢出状态；任何证据缺口都会进入 `INCOMPLETE`，不得静默丢弃。
- 文件哈希按块计算，长时会话收尾不再将全部记录复制到内存。

### 7. 试产协调层

- 抽取 `BatchCoordinator` 与 `FixtureSessionCoordinator`，统一状态迁移、资源租约、证据收尾和恢复入口。
- `ProductionWorkspace` 与 `FixtureDebugWorkspace` 只绑定协调器状态并发出命令。
- 保持 M19-A 与 M19-A.2 当前已实现行为，不在本里程碑扩展新的正式放行规则。

### 8. 国际化、样式与质量门禁

- 页面自行维护稳定翻译键，语言切换不再依赖全对象树文本反查。
- 高频内联样式收敛为共享控件属性和语义样式，保留动态状态所需的最小样式更新。
- 增加架构测试：UI 不拥有协议解析器、隐藏页面无活跃渲染定时器、协议领域依赖单向、证据队列有界。
- 更新 AGENTS、架构说明和模块职责索引，使文档与实际代码持续一致。

## 实施顺序

1. 建立 M21 计划、验收标准和开发日志。
2. 落地页面生命周期和按需构建，先消除工作区切换卡顿。
3. 治理 SDB、后台回放和夹具长时证据，先消除内存随时长增长风险。
4. 抽取统一设备会话、控制器和遥测序列权威源。
5. 拆分协议实现并建立产品字段来源状态机。
6. 抽取试产协调层，收敛两个试产页面职责。
7. 收敛国际化、样式和架构质量门禁。
8. 执行全量回归、性能验证和文档对照验收。
