# M19-A.6 单设备自动报告开发记录

## 2026-09-19

- 已确认现有批次框架具备设备身份、attempt、metric、event、SDB 和共享电源证据，但尚无正式完成入口和报告生成器。
- 开始实现 ResultStore 报告状态、冻结快照、证据归档、DOCX V1/V2、审核及设置集成。
- ResultStore schema 升级到 v3，新增不可变报告快照、版本产物和一次性审核记录；v1/v2 数据库自动迁移。
- 新增 `ProductionReportService`，按日期/型号/SN/批次生成自包含 `evidence.zip`、V1/V2 DOCX 和 SHA-256 manifest。
- 批次结算统一由 `BatchCoordinator.complete()` 判定 completed/incomplete；报告失败记录为 generation_failed，不改变设备自动结论。
- 设置页增加报告根目录和品牌字段；工作站配置包嵌入品牌与 Logo，导入后可直接复用。
- 批次页增加“完成并生成报告”和“审核报告”入口；审核必须填写姓名、最终结论和原因。
- DOCX 模板使用中文 A4 正式质量报告布局，长表跨页重复表头并禁止拆分单行。
- 全量测试：1342 passed；翻译目录检查：1223 messages 全部完成。
- 使用标准 `render_docx.py` 生成 8 页示例，并配置系统中文字体后逐页检查通过。
- 用户复核发现当前报告只有标量指标和证据索引，缺少全程 SNR、姿态、收敛/发散曲线及分阶段分析；确认该版本不足以作为工程判读报告。
- 已确认 SDB v3 记录主机 UTC 纳秒时间，ResultStore 事件同时记录 UTC 与单调时钟，可建立时间轴换算；SNR/姿态支持 Product Service 和 Profile 语义旧协议两种来源。
- 新增冻结曲线分析：按物理量选择 Product Service 或 Profile 语义来源，保存全程 SNR、锁定状态、roll、pitch、yaw 及 MS6222 姿态误差序列。
- 新增 attempt 时间窗统计：样本数、覆盖时长、均值、标准差、极值、首尾中位数、变化量、斜率和趋势；无配方阈值时仅形成可复算的描述性结论。
- Word 增加“过程曲线与阶段分析”，插入全程曲线、分阶段统计、阶段结论和最终过程总结；无 MS6222 数据时明确禁止姿态精度及收敛/发散判定。
- 设备正式录制现在把当前 Profile 写入 SDB v3 文件头，使旧 Debug DATA_REPORT 也能按语义恢复 SNR/姿态曲线。
- evidence.zip 增加 analysis.json、曲线 PNG、MS6222 comparison CSV 及 CSV 转 JSONL 证据。
- 全量测试：1344 passed；翻译目录检查：1223 messages 全部完成。
- 含三类曲线的 V1 示例渲染为 9 页 A4，修复动态章节后的空白页后逐页检查通过。
- 用户复核指出全程图加 attempt 表仍不足以表达真实工况；确认现有执行模型已有静态、锁定后摇摆、摇摆中上电、锁定后车载和车载中上电五个 test ID，但报告没有建立工况层次。
- 报告分类确定为四个一级工况；车载动态章节保留锁定后车载和车载中上电两个子场景，导航类测试作为跨工况汇总。
- 用户提供正式测试报告封面参考，确定改为右上编号、居中标题、产品信息、三级签署表和底部日期的版式，并在正文增加独立测试环境说明。
- 已完成新封面：报告编号置于右上分隔线上方，结论作为产品信息字段，签署表记录编写、审核和批准状态，成文日期取批次完成日期。
- 报告冻结快照增加工作站主机、操作系统、Python、时区和 UTC 偏移；“测试环境”独立列出地点、工位、软件、网络端点、电源、摇摆台、MS6222 及温湿度，缺失数据明确显示“未配置/未记录”。
- 四工况完整样例经标准 DOCX 渲染流程生成 14 页 A4；逐页检查封面、环境表、全程图、工况图、阶段分析和附录正常，并压缩证据索引消除单条内容占用尾页。
- 报告专项测试 9 passed；生产及报告相关测试 113 passed；全量测试 1346 passed。
