# DEBUG设备协议接口规范

## 1. 协议概述

DEBUG设备协议是用于softHertz调试工具与DEBUG设备之间通信的二进制协议，采用固定的帧格式和CRC16校验确保数据可靠性。本规范定义了协议的帧结构、命令类型、数据格式和通信流程，供其他设备实现对接使用。

## 2. 物理层与传输层

### 2.1 支持的通信方式

- **串口**：波特率可配置（默认115200bps），数据位8，停止位1，无校验
- **TCP**：基于TCP/IP协议，支持客户端/服务器模式
- **UDP**：基于UDP/IP协议，支持单播/广播模式

### 2.2 数据传输

- 字节顺序：小端序（Little Endian）
- 编码方式：二进制

## 3. 帧格式

### 3.1 基本帧结构

```
帧头 + 设备类型 + 命令类型 + 数据长度 + 数据 + 校验和 + 帧尾
```

| 字段       | 长度（字节） | 描述                   | 值                     |
|------------|--------------|------------------------|------------------------|
| 帧头       | 2            | 数据包起始标识         | 0xAA 0x55              |
| 设备类型   | 1            | 设备类型标识           | 0x0D                   |
| 命令类型   | 1            | 命令类型代码           | 0x01, 0x02, 0x03       |
| 数据长度   | 2            | 数据部分的字节长度     | 小端序                 |
| 数据       | 可变         | 实际数据内容           | 取决于命令类型         |
| 校验和     | 2            | CRC16-CCITT校验值      | 小端序                 |
| 帧尾       | 1            | 数据包结束标识         | 0xEE                   |

### 3.2 CRC校验算法

- **算法**：CRC16-CCITT
- **多项式**：0x1021
- **初始值**：0xFFFF
- **计算范围**：从帧头到数据部分（不包括校验和和帧尾）
- **实现示例**：
  ```
  def crc16_ccitt(data: bytes, poly=0x1021, init_val=0xFFFF) -> int:
      crc = init_val
      for byte in data:
          crc ^= byte << 8
          for _ in range(8):
              if crc & 0x8000:
                  crc = (crc << 1) ^ poly
              else:
                  crc <<= 1
              crc &= 0xFFFF
      return crc
  ```

## 4. 命令类型

### 4.1 数据上报 (CMD_DATA_REPORT = 0x01)

#### 功能
DEBUG设备向调试工具上报实时通道数据。

#### 数据格式
```
时间戳（4字节） + 通道数量（1字节） + 通道数据[通道数量]
```

##### 时间戳
- 格式：4字节无符号整数
- 字节序：小端序
- 单位：毫秒（相对于设备启动时间）

##### 通道数量
- 格式：1字节无符号整数
- 范围：1-16

##### 通道数据
每个通道数据包含：
```
通道名称（32字节） + 通道值（4字节）
```

- **通道名称**：UTF-8编码字符串，不足32字节用0x00填充
- **通道值**：单精度浮点数（float），小端序

#### 示例帧
```
AA 55 0D 01 00 20 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 EE
```

### 4.2 命令响应 (CMD_COMMAND_RESPONSE = 0x02)

#### 功能
DEBUG设备对调试工具发送的命令进行响应。

#### 数据格式
```
响应码（1字节） + 响应消息（可变长度）
```

- **响应码**：0表示成功，非0表示失败
- **响应消息**：UTF-8编码的文本消息，可选

#### 响应码定义

| 响应码 | 描述           |
|--------|----------------|
| 0      | 成功           |
| 1      | 无效命令       |
| 2      | 参数错误       |
| 3      | 设备忙         |
| 4      | 内部错误       |
| 5      | 不支持的操作   |

#### 示例帧（成功响应）
```
AA 55 0D 02 00 00 00 01 4F 4B EE
```
（响应码0，消息"OK"）

### 4.3 Debug模式控制 (CMD_DEBUG_CONTROL = 0x03)

#### 功能
调试工具控制DEBUG设备的Debug模式开关。

#### 数据格式
```
启用标志（1字节）
```

- **启用标志**：0表示禁用Debug模式，1表示启用Debug模式

#### 示例帧（启用Debug模式）
```
AA 55 0D 03 00 01 01 EE
```

## 5. 通信流程

### 5.1 数据上报流程

1. DEBUG设备收集各通道数据
2. 构建数据上报帧（包含时间戳、通道数量和各通道数据）
3. 发送帧到调试工具
4. 调试工具接收并解析帧，验证CRC校验
5. 调试工具根据解析结果更新显示或存储数据

### 5.2 Debug模式控制流程

1. 调试工具构建Debug模式控制帧
2. 发送帧到DEBUG设备
3. DEBUG设备接收并解析帧
4. 执行Debug模式开关操作
5. 构建命令响应帧，包含操作结果
6. 发送命令响应帧到调试工具
7. 调试工具接收并解析响应

## 6. 错误处理

### 6.1 帧解析错误

调试工具在解析帧时可能遇到以下错误，设备应确保发送正确的帧格式：

- **帧头错误**：数据包开头不是AA 55
- **帧尾错误**：数据包结尾不是EE
- **设备类型错误**：设备类型不是0D
- **长度错误**：实际数据长度与数据长度字段不符
- **CRC错误**：计算的CRC值与接收到的CRC值不符

### 6.2 通信错误

- **超时**：设备应在合理时间内响应命令（建议不超过1秒）
- **重发机制**：调试工具可能会对未收到响应的命令进行重发

## 7. 注意事项

1. **数据完整性**：设备应确保发送的每帧数据都完整、正确，避免数据丢失或损坏
2. **实时性**：对于数据上报，建议上报频率不超过1000Hz（1ms间隔）
3. **资源管理**：设备应合理管理资源，避免因通信导致的性能问题
4. **兼容性**：设备实现应严格遵循本规范，确保与调试工具的兼容性
