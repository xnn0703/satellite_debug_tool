## 2026-08-17：批次参与设备门禁修正

### 源码核对与契约

- `FleetController` 和 `FixtureCoordinator` 原本均支持 1~4 台设备，结果库也只限制上限 4 台；不存在底层必须四台的判断。
- 现场看到的“必须四台”实际来自 Production Workspace 的“开始批次”按钮永久禁用且没有处理函数，并非在线设备计数错误。
- 本轮将并发容量与开始门限分离：当前在线、已识别且录制器已 ARMED 的设备达到 1 台即可开始，最多纳入 4 台；空槽和离线历史会话不阻塞。
- 开始时冻结参与设备身份与槽位并写入批次证据，随后只为冻结名单创建初始 attempt。批次运行后出现的新设备不得自动加入本批判定。

### 实施与验证

- `ProductionResultStore.start_batch()` 在一个 SQLite 事务内冻结 1~4 台参与设备、把其他已登记设备标记为 `excluded`、切换批次到 RUNNING，并为每个参与设备创建首轮 attempt。
- Production Workspace 的开始按钮改为动态门控：1 台在线即可启用；要求身份已确认、录制已 ARMED 且身份已持久化。批次开始后新设备仅记录忽略事件，不创建 attempt，也不进入该批录制。
- `FleetController` 同步冻结录制参与者，未入选会话立即完成暂存录制；批次中止会终止活动 attempt、结束各参与设备录制并留下状态事件。
- AFD01 Product Service 新增 `SERVICE_NAV_SOURCE_INFO(0x2A)` 和 `SERVICE_EXTERNAL_INS_DIAGNOSTICS(0x2B)`，服务版本升至 6。设备从参数区读取 GNSS/IMU/姿态来源，从 Bynav 驱动读取在线、报文频率/计数、CRC/格式错误、RX 溢出和最新姿态/精度量。

## 2026-08-09：外部 INS 与整机组合导航分层

### 源码核对

- AFD01 已保存 Bynav 外部 INS 的对准/解算状态、定位类型、姿态、姿态/位置/速度标准差、solution/differential age，以及报文频率、计数、CRC/格式错误和 RX 溢出等内部数据。

## 2026-08-09：MS-6222 独立姿态参考审查

### 输入资料

- `MS-6222使用说明书-V1.03.pdf`，SHA-256 `cd58a2e7c2b9ff75b75f03a30a6209d70ac2a3169eb94c813f112a1ebfd4bc9a`。
- `版本变动对比.docx`，SHA-256 `91904db20c441de3ce0094d1c0e3da0023d1d9baaf5360bee698eb5dfcb7f989`。

### 审查结论

- MS-6222 可作为灵境摇摆台的独立姿态测量反馈。当前 Roll/Pitch `±15° @ 0.25 Hz` 的峰值角速度约 23.6°/s，Yaw `±15° @ 0.1 Hz` 约 9.4°/s，低于其 `±250°/s` 陀螺量程；100 Hz 组合导航输出满足当前轨迹采样密度。
- 手册的双天线航向 0.1° RMS 以 2 m 基线为条件，姿态 0.1° RMS 以 GNSS 有效为条件；文档未给出动态带宽和固定输出延迟，因此不能仅凭规格把设备定义为计量真值。
- `INSPVAXB` 提供 GPS 时间、INS 状态、三轴姿态和三轴标准差。新版 GNSS 报文增加航向有效位、基线长、从天线卫星数和航向标准差，可用于质量门控。
- V1.03 手册与后续版本变更的 GNSS 字段不同。版本记录还包含天线轴向、持续转动和运动中启动修复，正式试产必须冻结包含这些修复的稳定固件和对应协议，不能直接使用未验证 beta。
- 车辆动力学约束会把侧向和垂向速度约束为零，不适合六自由度摇摆台，参考配置必须关闭该约束。

### 接入决策

- 新增共享 `Ms6222ReferenceAdapter` 设计，使用隔离 RS-422、460800 baud，采集 `INSPVAXB 100 Hz`、`GNSS 10 Hz` 与 PPS。原始帧、CRC、主机单调时间、PPS、解析 schema、固件和配置哈希全部保存。
- MS-6222 使用独立常供电，不随四台 DUT 共享 PSW 输出断电；两根天线需要开阔收星和已测量的刚性基线。平台命令到参考评价夹具，参考到 DUT 评价设备，两级误差分开计算。
- 坐标对齐使用带版本的四元数变换；时间链建立 `MS-6222 GPS/PPS -> 主机单调时间 -> AFD01 设备时间` 模型。当前轨迹峰值角速度下，1 ms 时间误差约形成 0.024° 动态角误差，不能只使用串口回调时间声明高精度相位/姿态结果。
- 未资格验证时，MS-6222 只能提供 `MOTION_OBSERVED`。完成静态、逐轴、幅频、60 min 组合轨迹、运动中启动、更高等级参考对比及不确定度评估后，才允许产生 `POSE_VERIFIED`。
- 参考不确定度不足以覆盖 DUT 门限、质量门控失败、安装/基线变化、固件升级或资格过期时，报告只保留测量值和趋势，不给绝对姿态 PASS。

### 当前边界

- 本轮只更新 M19 计划、验收标准和开发记录，尚未实现 MS-6222 驱动或时间同步硬件。
- 实施前仍需确认实际双天线基线、开阔测试场地、稳定固件/协议、独立电源、RS-422/PPS 采集器、参考资格门限和复验周期。

## 2026-08-09：GW Instek PSW 80-27 电源协议审查

### 输入资料

- `PSW80_27E_CTRL.m`，SHA-256 `929d7a6b6d80ed4a82439d4f304255095a9072822b1f4cfe4edab28844c97d70`。文件为 GB18030/CRLF，已转码只读审查。
- `电源控制协议参考.md`，SHA-256 `89328e33bf805306e9f53ee3f7d0374f83d8f75477eb082f463a92dc61d5a168`。
- GW Instek 官方 PSW Series Programming Manual（2024-11-06）和 PSW Series 产品页。

### 已确认协议事实

- 目标设备为 GW Instek PSW 80-27，而不是参考文档标题中的 TDK-Lambda。官方规格为单通道 0~80 V、0~27 A、720 W。
- 参考文档中的 GPP-4323 USB 串口章节不属于当前局域网电源，首期不实现该适配器。
- LAN socket 使用 TCP 固定端口 2268，消息按 LF 结束；面板需设置 F-36=1、F-57=1，固定 IP 时关闭 DHCP 并设置 F-39~F-50。
- MATLAB 样例端点是 `192.168.1.108:2268`，设置示例为 14 V/2 A；该电压/电流尚未被确认为四台设备共电的正式配置。
- `*IDN?` 可返回厂家、型号、SN 和固件；`OUTP?` 可确认逻辑输出，`MEAS:ALL?` 可一次读取实际电压与总电流。
- `STAT:OPER:COND?` 可识别 CV/CC，`STAT:QUES:COND?` 和 `OUTP:PROT:TRIP?` 可识别限压/限流、OV/OCP/OTP、掉电和关断等异常；`SYST:ERR?` 提供错误队列。
- `*OPC?` 只确认命令处理完成，不证明物理电压存在；`SYST:COMM:RLST LOC` 只返回面板本地控制，不改变输出状态。

### 接入决策

- 新增单连接、单待响应的 `GwInstekPswAdapter`；TCP 接收按 LF 累积，禁止多个线程并发查询同一 socket。
- 上电采用身份确认、输出 OFF、实测低电压、设定值写入/读回、错误检查、`OUTP 1`、输出状态、实测电压和各设备 Boot Session 的分层闭环；电源前三层是共享动作，Boot Session 和收敛计时按设备独立推进。
- 断电采用 `OUTP 0`、状态 OFF、实测电压低于阈值、设备离线和 `off_dwell_s`；TCP 断线或应用重启后不自动恢复输出 ON。
- 长时测试记录实际电压、总电流、CV/CC、保护和错误。PSW 是单通道，四台设备只能得到聚合电流，不能以总电流除以四作为单台功耗。
- 一台异常拉流可能影响全部 DUT，正式线需要每路支路保险丝或电子保护。软件闭环不替代实体 OUTPUT/急停或独立安全回路。

### 当前边界

- 本轮只更新 M19 计划、验收和开发记录，尚未实现 PSW 驱动。
- 实施前仍需确认四台共电的正式电压、电流等级、OVP/OCP 策略、电压/总电流阈值、断电驻留时间和支路保护方案。

## 2026-08-09：60 min 工况与性能指标口径

### 时长决策

- 正式试产中的每个持续性物理工况均采用不少于 60 min 的有效观测窗口，用于覆盖姿态慢漂、热稳定变化、偶发失锁和长周期数据缺口。
- 60 min 从前置条件稳定收敛后开始，不包含等待上电、导航初始化、姿态收敛或跟踪捕获时间；这些过程单独计时并进入报告。
- 有效观测开始后，失锁、降级和重捕属于测试结果，不暂停计时。夹具动作失效、车辆工况中断或证据流长时间中断则使 attempt 为 `INCOMPLETE/ABORTED`。
- 九项结果复用五个共享物理窗口：冷启动静置、锁定后摇摆、摇摆中上电、锁定后行驶、行驶中上电。静态 GNSS 与 IMU 共用冷启动静置窗口，四台设备并行测试，因此完整正式批次约需 5 h，加上收敛、回中、换场和重测时间。
- 开发阶段可使用短配方加速联调，但产物必须标记 `ENGINEERING_ONLY`，不得形成正式 PASS。

### 报告指标

- 每个工况报告导航就绪、姿态首次/稳定收敛、首次/稳定锁定的分级耗时，稳定事件必须满足门限和连续驻留时间。
- 有参考 IMU 时，使用时间对齐且坐标标定后的姿态误差四元数，输出三轴均值、标准差、RMS、P95、P99、最大值、峰峰值、首末 5 min 中位数差和稳健趋势斜率。
- “综合姿态漂移”定义为三轴漂移向量模，不把三个欧拉角简单相加；动态工况另报告幅值比、主频误差、相位差/时延和残差 RMS。
- 跟踪性能报告锁定可用率、失锁次数/总时长/最长时长、重捕 P50/P95/最大值，以及 SNR 中位数、P5/P95、基线变化、趋势和低阈值持续时间。
- GNSS、PLL、组件状态、温度和数据缺口与姿态/SNR异常使用同一时间线关联；原始 SDB 保留全量数据，PDF/HTML 只做保峰值的可追溯降采样。

### 真值边界

- 推荐在摇摆台固定独立参考 GNSS/INS 或参考 IMU，并保存安装方向、坐标变换、时间偏移和标定版本。
- 平台命令与参考 IMU 的差异用于评价夹具，参考 IMU 与 DUT 的差异用于评价设备，二者不得混算。
- 没有独立参考时，四台 DUT 共识只能用于发现离群和证明运动发生；报告只能使用“输出相对漂移/输出稳定时间”，不能宣称绝对姿态误差、综合姿态漂移或真实收敛精度。

### 长时运行影响

- 摇摆台以 10 Hz 运行 60 min 时约下发 36 000 条 A6T。调度器必须使用绝对单调时间，跳过过期点而不突发补发，并记录抖动、跳点、最长间隔和有效覆盖率。
- 批次开始前应依据首分钟实测码率、剩余工况和安全系数预估磁盘空间；空间不足时禁止正式启动。
- 本轮只同步计划、验收标准和开发记录，未修改运行代码或设备协议。

## 2026-08-08：需求与现状审查

### 用户目标

- 固件版本、参数系统、五类跟踪场景、GNSS 和 IMU 静态性能逐项测试。
- 测试人员录入本批固件/参数标准，由上位机读取设备实值并核验。
- 最多四台不同 IP 的设备同时探测、连接、提示、录制、分析和出报告。
- 每台设备拥有独立报告和独立原始证据。
- 四台设备共享同一局域网电源、载具和摇摆台，物理激励并行执行。
- 局域网电源和摇摆台由上位机自动控制，车辆继续由测试人员人工驾驶。

### 当前源码事实

- 当前 `LiveView` 是单设备聚合对象，拥有一个 worker、握手、store 和 recorder；不适合直接复制成四个可见 Live 页面。
- `UdpWorker` 固定一个远端 endpoint。多实例共享同一本地端口会产生接收归属风险，因此 M19 使用一个 Hub 按来源 endpoint 分流。
- 单机 UDP 已支持先绑定后等待设备、重连和录制 ARMED；这些状态语义可复用于批量会话。
- Product Service 已覆盖身份、跟踪、锁定、导航、姿态、波束、SNR、位置、组件、链路和 PLL 状态。
- 参数表协议可用于只读核验，但当前事务逻辑耦合在 `DeviceView`，需要抽出无 UI 客户端。
- SDB v3 已支持主机时间、原始 RX、控制、metadata、gap 和 summary，可作为每台设备证据容器。
- GNSS store 可区分卫星记录、信号锁定/使用和 C/N0；绝对定位精度仍需要外部基准点。
- 当前 AFD01 Profile 没有足以验收 IMU 静态性能的原始六轴或生产统计；需要设备侧新增类型化窗口统计。
- 当前没有批次数据库、流程状态机、指标引擎或报告生成器。

### 架构决策

- 新增独立 Production Workspace，不改客户/工程模式的含义。
- 首期使用共享 UDP Hub + 最多四个隔离 DeviceSession。
- 测试标准数据化为不可变配方，不把阈值硬编码进 UI。
- 每次测试 attempt 追加保存，人工改判不覆盖自动结果。
- SQLite 保存业务结果，SDB 保存原始证据，报告从持久化数据重建。
- 新增批次级 `FixtureCoordinator`；共享电源/摇摆动作只执行一次，各设备 attempt 引用同一动作并独立判定。
- 局域网电源和摇摆台使用类型化适配器，车辆使用人工门禁。设备会话不得直接操作共享夹具。
- 不恢复任何面向用户的仿真入口；自动化测试使用离线协议 fixtures。

### 灵境平台协议审查

- 已完整审查《南京灵境平台通讯协议》PDF 中的“运动平台控制协议 V0.3”。
- 协议为 UDP，默认端口 9800，ASCII 包络为 `@<command>:<values>#`，角度单位为度、距离单位为毫米。
- 姿态命令包括 `A3/A3T`（Roll/Pitch/Z）和 `A6/A6T`（Roll/Pitch/Yaw/X/Y/Z）；`T` 变体最后一个参数为期望完成时间。
- 文档没有定义 ACK、查询、当前位置回读、心跳、停止、回零或急停；因此 UDP 发送成功只能记为 `COMMAND_SENT`。
- 协议含缸长、旋转轴和 12 路继电器特效输出，M19 不使用这些低层/附加能力，特效输出固定关闭。
- 原理章节写右手坐标系，协议章节写左手坐标系，存在明确冲突；首次接入必须低幅度逐轴标定，不能按文字直接硬编码。
- 现场已确认使用 A6/A6T：三轴摇摆时 X/Y 固定为 0，工作高度 Z=100 mm。
- 回中为 Roll/Pitch/Yaw/X/Y=0、Z=100 mm；复位为全部 0。流程中止默认回中，不自动执行复位。
- 平台速度由 A6T 的完成时间控制，不另设速度字段；每个运动段保存 `duration_ms`。

### 无回读接入决策

- 平台适配器记录原始命令、目标姿态、完成时间、发送结果和主机单调时间，禁止把“已发送”显示成“已到位”。
- 摇摆曲线使用逐目标定时下发，不预先灌入多条指令；在厂家未确认幂等前不盲目重试定时命令。
- 推荐台面增加独立参考 IMU。没有参考 IMU 时，可用至少两台 DUT 的姿态共识确认运动发生，但不能作为平台绝对角度或单台 IMU 性能真值。
- 软件中止只能尝试发送 Z=100 mm 的回中姿态，不替代物理急停。停止和急停能力仍需继续向厂家确认。
- 全局夹具事件采用工作站单调时间，四台设备保留各自 uptime；报告通过同一 `fixture_action_id` 对齐证据窗口。
