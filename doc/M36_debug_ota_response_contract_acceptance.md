# M36 旧固件 OTA 响应合同迁移验收标准

## A. 根因回归

- [x] 用 `0.0.130_beta` 的 `OK` 响应稳定复现当前上位机停在 BEGIN 并超时。
- [x] 新实现识别该设备属于旧合同后，BEGIN、每个 DATA 分片和 END 均只由对应通用成功文本推进。
- [x] 旧合同收到已知设备失败响应时立即显示拒绝原因，不等待定时器超时。

## B. 正式合同

- [x] 修复后固件对 BEGIN 返回 `OTA_BEGIN=READY`。
- [x] 修复后固件对 DATA 返回包含实际序号的 `OTA_DATA=<seq>`。
- [x] 修复后固件仅在长度和 CRC 校验完成后返回 `OTA_END=VERIFIED`。
- [x] 修复版本及更高版本收到 `OK`、错误序号或其他阶段响应时不推进 OTA。

## C. 迁移边界

- [x] 旧合同只对已认证解密客户包、已注册产品和明确低于修复版本的设备启用。
- [x] 型号未知、版本未知、版本冲突或修复版本及更高版本均使用严格合同或拒绝开始。
- [x] 参数、Debug 和其他无关响应不能被旧合同误消费。
- [ ] 升级回机后上位机确认同 endpoint、不可变身份和目标版本；同版本重装仍显示“应用未独立确认”。

## D. 失败与恢复

- [x] BEGIN 拒绝、DATA 拒绝、分片超时、CRC 失败、断线和会话变化均释放事务 owner。
- [x] 已进入传输后的显式拒绝执行有界终止流程并保留未知结果证据。
- [x] OTA 失败不破坏所选不可变 artifact，也不改变包认证或版本准入结论。
