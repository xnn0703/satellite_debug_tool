# M32 正式试产与夹具配置收口开发记录

## 当前状态

- 状态：配置与运行前门禁阶段已完成；正式工况执行器和 M31 整备继续实施
- 日期：2026-10-10

## 架构审查结论

- 三个夹具均已有控制通路，可以进入正式收口；每批仍需执行运行前预检。
- 当前连接配置分散在生产目录、独立摇摆台档案和 settings，批次无法冻结完整工作站事实。
- MS-6222 缺少正式 reference profile，是 COM 配置无法进入自动化页面的直接原因。
- `StationProfile` 只存 motion/reference ID，resolve 不解析依赖，配置包也不携带夹具档案和标定。
- 现有 `ProductionRunCoordinator` 是 attempt owner，但真实硬件执行器未接入；工程预览文案不能只靠改字删除。
- M31 已获用户确认，应与工作站配置和正式流程一起实施，避免建立第二套配置或执行状态源。

## 2026-10-10 实施记录

- 生产配置升级到 v2，新增 `ReferenceSensorProfile`，保存 MS-6222 COM、固定
  460800 波特率、安装身份、质量门限和坐标标定 ID。
- `resolve()` 现在解析电源、摇摆台、MS-6222 和已确认标定；缺失档案、
  `PENDING-*` 标定、标定与档案 SHA 不匹配均拒绝进入正式批次。
- 批次快照冻结三类夹具完整 payload、revision 和 SHA-256；配置包 v2 携带
  摇摆台档案、MS-6222 档案和坐标标定，并验证冲突和哈希。
- 生产配置页面增加摇摆台和 MS-6222 页面。摇摆台端点允许按工位配置，型号
  预置继续拥有几何、包线和 FRD 符号；MS-6222 支持枚举及手工输入 COM。
- 工位档案使用下拉框绑定电源、摇摆台和 MS-6222，批次摘要显示实际端点。
- 旧 `production.ms6222_port` 在具备唯一已标定摇摆台时一次性迁移到
  `ms6222-main`；迁移后正式业务只读取 reference profile。
- `FixtureRuntime` 增加肯定式状态事实；夹具页面将连接、有效帧、运动和故障
  同步到批次页。正式开始门禁要求摇摆台与 MS-6222 都达到 `READY`。
- 删除生产页和解锁对话的“工程预览/待验证”表达，改为工作站档案及实时预检
  合同。配置完成不等于连接或就绪。
- 定向回归 78 项通过；全量首次运行 1461 通过、1 项旧端点归属断言失败。
  该测试已按“端点属于工位安装、几何与 FRD 属于型号”合同修正；最终全量
  `1463 passed`，翻译检查、`compileall` 和 `git diff --check` 通过。
