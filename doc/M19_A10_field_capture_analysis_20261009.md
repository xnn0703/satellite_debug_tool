当前自动分析得到的候选映射为：传感器轴顺序与 Roll/Pitch/Yaw 一致，符号为 `[-1, +1, -1]`。该符号关系得到六个正负方向动作的一致支持，但因为标定记录仍为 `confirmed=false`，以下数值只能作为工程分析，不能写入正式运动精度结论。

Yaw 需要继续确认：

- 起始中心位到结束中心位的变化为 Roll `-0.0006°`、Pitch `+0.0059°`、Yaw `-0.4703°`；
- Yaw 正负动作存在约 `0.18..0.24°` 的非对称误差；
- 各静态阶段内部的 Yaw 标准差约为 `0.0006°`，因此 `0.47°` 不能解释为短时随机噪声；
- 现有算法把中心位差异吸收到 Yaw “静态噪声”字段中，会掩盖回中重复性、机械间隙、航向漂移或安装标定问题，必须修正指标模型。

最后一次完整回原点的时间关系为：

|---|---|---|
| 发送 `0x03` | 15:12:02.858 | PC 到控制器命令 |

### 10.4 Roll 32°限位与恢复

15:11:35.132 发送的 Roll 32°目标为：

```text
7900000, 7900000, 2135765, 1853735, 1853735, 2135765 pulse
```

前两轴目标恰好等于 `200 mm × 39500 pulse/mm = 7900000 pulse`，证明超大姿态没有被拒绝，而是由运动学分别钳位到电缸软件行程上限。这不是安全的姿态限位模型，因为钳位后的六轴组合不再代表请求的刚体姿态。

运动约 2.413 s 后，轴1出现 `0x7121`。供应商随程序附带的 CiA402 错误表将其定义为 `Motor blocked`。错误持续约 10.0 s；最接近目标时六轴最大误差仍为 17240 pulse，约 0.436 mm。轴1随后从接近行程上限的位置回退。

整个故障期间反馈仍为：

```text
systemstate = 4
reccmd = 0xC0
reccmdret = 0
```

因此 `systemstate=4` 和 `reccmdret=0` 只能证明位置模式通信仍在运行，不能证明运动完成或无故障。六轴伺服错误码必须进入动作状态机和最终判定。

15:11:46.960 发送 Roll 0°，目标为六轴 3948420 pulse。该目标内部一致，并没有出现单轴错误目标；它与“平台回中”的 3950000 pulse 相差 1580 pulse，即 0.04 mm，来源于逆运动学几何零位和固定 100 mm 回中值的差异。

Roll 0°发送后：

- 轴1 `0x7121` 在约 0.58 s 后消失；
- 轴1间歇出现 `0x6320`，供应商表定义为 `Parameter error`；
- 六轴在 5.831 s 后实际到达 Roll 0°目标；
- `reccmdret` 全程保持 0，没有给出“仍在运动”或“恢复完成”的变化。

所以现场看到的非预期姿态不是 Roll 0°报文目标错误，而是供应商上位机在真实六轴尚未回到目标时提前判定完成。随后 15:11:56.015 的独立回中指令在 2.698 s 后到达 3950000 pulse 中心位。

### 10.5 `reccmdret` 当前可确认的语义边界

| 场景 | `reccmd` | `reccmdret` | 可确认事实 |
|---|---:|---:|---|
| 正常位置运动 | `0xC0` | 0 | 位置模式通信正常，但不代表到位 |
| 轴1 `0x7121/0x6320` 故障 | `0xC0` | 0 | 有伺服错误时仍为0，不能代表成功 |
| 回原点反馈恢复 | `0x03` | 1 | 与回原点过渡/恢复稳定关联 |

`reccmdret` 必须结合 `reccmd` 解释，不能建立全局“0成功、非0失败”规则。本次仍没有捕获明确的拒绝或忙状态。

## 11. 物理急停抓包分析

`急停.pcapng` SHA-256 为 `d7342221662872be56646bfb3cd95932b494ad0fd58075c841e855687d1b596c`。文件包含1186条控制器反馈和1条急停恢复后的平台回中命令。

急停前最后反馈为：

```text
15:42:23.729
sequence_id = 91527
controller_time = 2085820
systemstate = 4
reccmd = 3
reccmdret = 1
```

之后没有出现PC发送的停止、暂停或急停协议帧。反馈中断8.967 s后，控制器从以下状态重新开始：

```text
15:42:32.696
sequence_id = 3
controller_time = 3904
systemstate = 1
reccmd = 0
reccmdret = 0
axis_position = 0, 0, 0, 0, 0, 0
```

序号和控制器时间同时复位，证明物理急停导致控制器重启或等效掉电复位，不是软件快速停止。启动阶段出现约5.584 s和5.150 s的稀疏反馈间隔，15:42:43.800恢复 `systemstate=4`。从急停前最后一帧到恢复CSP共约20.071 s。

恢复后在15:42:50.314发送中心位，六轴约1.066 s进入250 pulse容差并最终精确到达目标，期间没有伺服错误。

直接控制owner必须把以下任一证据视为控制器重启：

- 序号明显回退；
- 控制器时间回退；
- `systemstate`重新进入启动状态1；
- 反馈长时间中断后身份代际变化。

重启后必须使当前动作失效，清除旧目标和完成状态，重新确认CSP、当前位置和六轴错误码后才能接收新动作。物理急停是当前已验证的紧急停止通道；抓包没有发现软件急停帧。

## 12. 硬限位与取消定位边界

现有证据只能确认：

- 超范围姿态被逆运动学逐轴钳位到0..200 mm；
- Roll 32°使轴1报告 `0x7121 Motor blocked`；
- 反馈结构没有独立硬限位位；
- 供应商页面没有取消定位入口；
- 静态反编译虽然发现快速停机和取消定位枚举，但当前 `ECMPlatform` 路径没有实现可调用的 `StopPlat`，供应商服务也没有调用这些命令。

因此当前产品合同应表述为：**没有可用的硬限位反馈合同；取消定位和软件快速停止在当前供应商控制路径中未实现；紧急停止依赖物理急停。** 是否存在未接入协议的物理限位开关仍需电气图或控制柜接线证据确认，不能由抓包单独证明其物理不存在。
