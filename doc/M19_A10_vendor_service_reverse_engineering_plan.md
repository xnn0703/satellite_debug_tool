# M19-A.10 灵境平台服务静态反编译与内部实现可行性计划

## 目标

- 以互操作和现有设备维护为目的，静态分析用户提供的 `ProConvert.exe`、`StewartPlat.dll`、PDB、配置和通讯协议。
- 建立从 UDP A6/A6T 文本到运动学、控制器通信、伺服状态和故障处理的真实调用链。
- 判断内部实现可以覆盖的边界，并形成可验证、可回退的最小原型路线。

## 边界

- 本阶段只做静态反编译、离线调用链复原和纯计算测试，不向真实控制器发送 EtherCAT、伺服使能、回零、复位或运动指令。
- 不修改当前 `LingjingPlatformServiceController`，Windows v1.5.0 继续使用已验证的厂家服务程序。
- 不把反编译源码或第三方符号文件提交到仓库；仓库只保存事实摘要、接口模型、测试向量和自主编写的代码。
- 只有在控制器状态机、限位、急停、故障恢复和完成回读合同均可证明后，内部实现才允许进入真机低幅验收。

## 工作项

1. 固定 EXE、DLL、PDB、协议和配置文件的 SHA-256。
2. 枚举托管程序集、类型、字段、方法、事件、P/Invoke 和外部程序集引用。
3. 反编译 UDP 9800 监听、A6/A6T 解析、参数换算和 `StewartPlat.dll` 调用链。
4. 反编译 Stewart 平台的几何参数、逆运动学、插补、轴限位和单位换算。
5. 定位控制器传输层，包括目标地址、端口、帧格式、命令字、状态字、错误码和重连路径。
6. 定位伺服使能、回零、停止、急停、故障复位和执行完成判定。
7. 将确认事实整理为领域接口；未知或只靠命名推测的部分保持“待确认”。
8. 若协议足够完整，先实现不接硬件的离线兼容原型，并用反编译出的固定输入输出向量验证。

## 交付判断

- `可直接内部实现`：上层协议、运动学、控制器写入、状态回读和安全状态机都有确定实现与测试向量。
- `可复用 DLL 做无界面 helper`：DLL 暴露稳定公共 API 且内部封装控制器和安全状态机，但跨平台仍不可行。
- `只能继续托管厂家服务`：关键控制路径位于未提供的原生组件、硬编码控制器固件合同或无法验证的状态机中。

## 验证

- 类型和方法清单可由两个独立工具或元数据与 IL 交叉确认。
- 关键调用链必须给出具体类型、方法和调用目标，不以字符串或文件名推断。
- 所有自主实现先运行离线单元测试；真机动作需要另行计划、现场安全确认和逐级低幅验收。
