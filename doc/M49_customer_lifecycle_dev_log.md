## 实现与事实来源

1. **客户电源显式连接**：`CustomerEndpointSessionBundle` 构造和页面活动过去都把可见性转换为 monitor.active，已有 host 就会创建 worker。删除两处自动激活源；“保存并连接”通过唯一 monitor.resume_monitoring 发起连接。工作区隐藏结束闲置会话，网络测试只保护已显式建立的会话，返回页面保持停止。既有释放本地控制合同保留。
2. **断连布局**：长状态、模块详情、身份及数值标签的内容宽度过去参与最小宽度计算；SNR 的 stale 文案还和大号数值一起换行。改为受容器宽度约束，完整文字放在 tooltip，状态字段左对齐；数值及小号质量状态分行。保留原有高度密度策略。曾尝试状态行换行并加高，最小窗口回归出现额外滚动，已撤回这一实现。
3. **可见命名**：自动化工作区标题、解锁提示及电源切换提示改用 Automated testing / 自动化测试，内部 production 与批次合同保持。
4. **录制连续性**：构造/显示 Shell 与夹具弹窗未发现主动停止 Runtime recorder 的调用。补充真实本机 TCP Shell 连接与夹具弹窗反复开关的组合回归，覆盖 passive 和 support_full 两种录制；同一 recorder/lease 持续，8 个唯一时间帧均进入 SDB。对旧弹窗 finished 信号加实例身份校验，防止延迟回调清掉新弹窗引用；没有以此声称修复现场录制中断。
5. **Shell 关闭事务**：旧链路在主窗口 shutdown 中确认/收尾后再次 close dialog，dialog 又自行确认；同步 worker.wait 及终排空 processEvents 让关闭事件和信号交错。改为 dialog 持有一次确认意图，controller 等待 worker.finished，workspace 分帧排空后关闭文本日志，随后自动重试原关闭。主窗口在结束设备录制前等待 Shell 完成，取消保持设备会话。删除旧阻塞终排空循环；线程结束和 link disconnected 使用不同事实。确认结果按枚举值比较，整数返回值回归稳定复现旧身份比较问题，但当前 macOS 原生返回没有复现该类型差异。

关闭失败保留日志 writer，明确反馈并允许重试；旧 dialog 的延迟 finished 信号只处理自身 owner。日志失败回归及 link 已断开而线程尚未结束回归覆盖此顺序。
