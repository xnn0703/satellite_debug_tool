# M60 摇摆台独立发送时间线计划

## 1. 触发依据

M58 已冻结升级条件：50 ms、预编译和有界绘图仍不能满足真实发送时间线时，将运动 UDP 调度迁移到独立进程，不保留第二套发送 owner。

`/Users/xmac/Desktop/测试.pcapng` 已满足该条件：1,507个轨迹帧中183个间隔超过60 ms，P95/P99为67.707/71.466 ms，最大75.491 ms；同期4,110个控制器反馈最大间隔21.379 ms。会话 `20261103T090727-0cabba45` 同时采集MS-6222，4,308个已发送点记录190个控制空洞。

## 2. 设计

1. `DirectMotionPlatformController` 保持平台状态、反馈、证据和动作完成的唯一owner。
2. 只有真实UDP socket启用独立时间线进程；测试传输和确定性假时钟继续使用进程内调度。
3. 子进程只接收不可变预编译帧、周期和停止意图，通过父进程socket的跨进程复制句柄执行 `sendto`；每次真实发送后重建下一周期，迟到不追赶突发。
4. 子进程回传实际发送时间、点索引和错误；父进程映射到权威编译程序并发布 `MotionCommandEvent`，不建立第二套平台状态。
5. 缓停意图由子进程按当前实际发送索引编译渐出段；父进程只在渐出完成后执行反馈闭环回正。
6. 应用退出先停止时间线进程，再关闭控制器socket和反馈线程。
7. ops/user入口均调用 `multiprocessing.freeze_support()`，保证打包程序可启动子进程。
8. 完整槽位迟到是可恢复的时序证据：保存 `timing_fault` 后立即发送当前点并继续，不跳点、不把一次晚唤醒扩大成无限期保持；UDP发送错误仍终止执行。

## 3. 验证顺序

1. 本机真实UDP socket验证跨进程复制、有限轨迹和缓停回正。
2. 注入父进程每点80 ms处理延迟，证明线上50 ms时间线不受父进程/GIL拖慢。
3. 执行运动组件、worker、生产执行、两版构建入口回归。
4. 分段执行完整测试集合。
5. 真实台架运行不少于10 min并抓包，比较指令P95/P99/最大间隔和MS-6222平顺性。

## 4. 证据边界

- 软件和loopback UDP证明进程隔离及状态合同。
- 只有新台架pcap能证明工作站真实网卡发送节拍。
- 只有MS-6222、机械观察和声音证据能确认物理卡顿与异响消失。
