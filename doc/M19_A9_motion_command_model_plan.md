# M19-A9 摇摆台运动指令模型收敛计划

## 1. 背景与已确认事实

- 灵境 A6T 合同以“一组绝对目标位姿 + 本次运动完成时间”描述一次运动。
- 供应商资料没有声明单次姿态目标只能变化 `2°`。
- 当前软件把自定义的 `max_step_deg` 同时用于档案字段、A6T 发送门禁、绝对运动拆分和周期轨迹离散步长门禁，导致一次绝对运动被拆成多次启停。
- UDP 写入成功只证明指令已发送。平台是否按期到位、实际轨迹是否连续，需要 MS-6222 或供应商侧状态提供独立证据。

## 2. 目标

1. 从夹具档案、运行配置、界面、序列化文件和测试中完整移除 `max_step_deg`。
2. 单轴移动、组合位姿、回中和复位均使用一条 A6T 指令表达目标与总完成时间。
3. 周期轨迹保留离散下发，但由连续轨迹、统一时间基准、速度/加速度门禁和调度质量保证平滑性。
4. 旧档案经过校验后迁移到新版本；迁移不保留已经失效的单步限制。
5. 在摇摆台测试页面提供一键自动资格测试，同时采集 MS-6222 原始数据、命令、目标和工程指标。

## 3. 数据模型与迁移

- 将夹具档案 schema 升级到 v3。
- `FixtureAxisLimits` 只保留：绝对角度、最大频率、最大角速度、最大角加速度。
- `MotionPlatformConfig` 删除全局和分轴的步长字段及 `axis_step_limit()`。
- 读取 v1/v2 档案时先按原始内容校验 SHA-256，再迁移为 v3；旧 `max_step_deg` 只作为被移除字段读取，不进入新模型。
- 新保存和导出的档案不再包含 `max_step_deg`。
- 档案编辑界面删除“单步角度”列，其他字段顺序和含义保持一致。

## 4. 绝对运动模型

- `AbsoluteMoveRunner` 对一个业务请求只发送一条 A6T。
- 发送前校验目标绝对角度、Z 范围、完成时间和安全前置条件。
- 发送后保持 busy 到该 A6T 的计划完成时刻；停止操作只阻止后续请求，不伪称已经终止平台当前运动。
- 命令证据记录一条原始 A6T、目标位姿、总完成时间、发送时间和 `COMMAND_SENT` 证据等级。

## 5. 三轴正弦轨迹算法

### 5.1 连续目标函数

每个启用轴使用同一单调时间基准：

```text
q(t) = A · e(t) · sin(2πft + φ)
```

- `A`：幅值。
- `f`：频率。
- `φ`：相位。
- `e(t)`：渐入/稳态/渐出的 `sin²` 包络；起止幅值和包络速度均为零。
- 三轴只共享时钟，不互相串行计算或下发，因此相位关系固定。

### 5.2 A6T 离散下发

- 轨迹开始时平台逻辑位姿必须已经确认。
- 以固定周期 `T` 调度；在第 `k` 个边界发送 `q((k+1)T)`，A6T 完成时间设为 `T`，让供应商服务在下一边界前插值到下一个目标。
- 最后一段精确落在包络终点，目标为零姿态；总时长不是 `T` 整数倍时使用最后的剩余完成时间。
- 使用绝对单调时钟计算每个 deadline，禁止用“上次发送后 sleep(T)”累积漂移。
- 调度晚到不足一个周期时记录 jitter；晚到跨过一个完整轨迹点时终止后续轨迹并报告 timing fault，禁止追赶式突发补发，也禁止跨点后仍用 `T` 强行追赶。

### 5.3 运动门禁

启动前对连续函数做常数时间解析校验：

- 姿态：`|q(t)|` 不超过轴绝对角度范围。
- 稳态正弦峰值速度：`2πfA`。
- 稳态正弦峰值加速度：`(2πf)²A`。
- 渐入和渐出同时计入包络的一阶、二阶导数，校验完整轨迹的保守速度和加速度上界。
- 采样周期必须不小于服务允许的最短完成时间。软件提供 `100/50/20 ms` 分级测试；先用 `50 ms` 验证，`20 ms` 必须通过服务程序接收能力、发送 jitter 和 MS-6222 实测轨迹后才能成为正式配置。

这里不再设置离散角度步长。相邻目标差由连续函数、采样周期以及速度/加速度门禁共同约束。

提高命令频率不自动等于更丝滑。如果服务程序每收到一条 A6T 都重新规划并在段尾降速，更高频率会产生更多速度边界。采样周期的选择以 MS-6222 实测的跟踪误差、边界速度尖峰和命令 jitter 为依据，不以界面刷新观感决定。

### 5.4 MS-6222 反馈与后续外环

M19-A9 先将 MS-6222 用作独立观测和验收来源，不在本次删除单步限制时直接改变运动控制结构。后续外环采用分层模型：

1. 灵境控制器及 EtherCAT 伺服仍是电机位置内环。
2. 软件生成连续参考轨迹，并按验证后的 `20~50 Hz` 频率发送 A6T。
3. MS-6222 以设备 GPS 时间为主时间戳输出姿态；主机接收时间只用于传输和调度诊断。
4. 先通过已知正弦扫频辨识“命令到实际姿态”的增益、相位和总延迟，再决定可用外环带宽。
5. 外环只计算小幅、限速、限加速度的目标修正；具有误差限幅、积分抗饱和、参考前馈和延迟补偿。
6. MS 数据过期、CRC/质量无效、时间链失锁、命令调度超期或误差持续扩大时，停止发送后续轨迹并形成故障证据。
7. MS-6222 不承担限位、急停和人员安全功能；这些功能继续由平台控制器和现场硬件负责。

在完成传感器固定延迟、平台频响、闭环稳定裕度和异常注入验证前，该外环只属于后续工程能力，不能进入正式批次自动测试。

## 6. 平滑性的证据边界

软件可以证明：目标函数连续、命令相位一致、完成时间连续、无累计漂移、无突发补发，以及请求没有超过配置的运动包络。

软件仅凭 UDP 发送记录不能证明机械运动丝滑。正式结论由 MS-6222 同步采集给出，至少检查：

- 三轴目标与实测姿态曲线；
- 跟踪误差 RMS、最大值和相位滞后；
- 速度曲线在采样边界是否出现周期性回零或尖峰；
- 渐入、稳态、渐出交界处是否连续；
- 指令发送 jitter、丢点和 timing fault。

若实测显示供应商服务在每条 A6T 边界都会将速度降为零，则现有 UDP A6T 合同不能满足连续轨迹，需要供应商提供轨迹缓冲、速度模式或更底层的周期位置接口；软件不通过提高下发频率掩盖该合同缺口。

## 7. 扩展轨迹与对星测试边界

- 确定性正弦、扫频和实测姿态时间序列可以直接作为平台参考输入。
- 海况谱必须结合目标船型、航速、航向和六自由度 RAO 生成船体运动时间序列；JONSWAP 或 Pierson-Moskowitz 波谱本身不是平台姿态命令。
- 实船 IMU 数据可以经过坐标转换、去偏、限幅、限速、限加速度和平台带宽筛选后回放。
- 摇摆台可用于非相控阵设备的稳定和对星性能测试，前提是负载质量、重心、安装刚度、运动范围、速度、加速度和电缆拖曳均在平台能力内。
- 完整对星结论还需要被测设备的方位/俯仰或云台反馈，以及卫星信标、锁定状态或 SNR 等 RF 证据。MS-6222 只证明基座实际姿态。
- 当前平台的有限角度和有限直线行程只能模拟局部船体扰动，不能复现船舶的大范围平移航迹。

## 8. 实施范围

- `core/production/fixture_profile.py`：档案 v3、旧档案迁移、删除单步字段。
- `core/production/motion_platform.py`：删除步长门禁和分段绝对运动，修正轨迹前视点、包络导数门禁和超期处理。
- `ui/fixture_debug_workspace.py`：删除单步角度列。
- `core/production/fixture_qualification.py`：自动资格测试的阶段、状态迁移和工程结果模型。
- 摇摆台页面显式获取摇摆台与 MS-6222 两项租约，自动执行回中、三轴正负方向、回中复核及证据收尾。
- 相关测试、翻译资源、M19 文档和 AGENTS 架构事实同步更新。

### 8.1 一键自动资格测试

默认工程序列为：

```text
中心静置
Roll +3° -> Roll -3°
Pitch +3° -> Pitch -3°
Yaw +3° -> Yaw -3°
中心静置复核
```

每个阶段均包含单条 A6T 运动、稳定等待和 MS-6222 采样窗口。自动结果至少保存：

- 命令是否发送、目标和完成时间；
- MS 有效帧数、输出频率、CRC/长度错误和数据缺口；
- 每个逻辑轴对应的 MS 传感轴及正方向；
- 正负方向响应幅值、增益、交叉耦合、静态噪声和回中偏差；
- 命令到姿态开始变化的工程延迟、10%~90% 上升时间和稳定窗口误差；
- 当前坐标标定是否有效，以及自动测试能否产生精度结论。

未配置或未确认坐标标定时，自动测试仍完成原始方向辨识并给出建议映射，但结论保持 `INCONCLUSIVE`，不得用同一组数据自标定后再宣称精度 PASS。

每次运行生成独立 `fixture_sessions/<session_id>/` 证据目录，并额外生成自包含 ZIP，供现场直接回传分析。ZIP 包含档案、命令、MS 原始帧、解析帧、目标/测量/误差、事件、自动测试摘要和 manifest。

## 9. 风险与恢复

- 旧档案迁移必须保留 endpoint、轴符号、标定 ID、绝对范围和周期包络；任何 SHA 不匹配继续拒绝加载。
- 一条大范围 A6T 会直接交给供应商服务执行，因此真机测试从小幅、长完成时间开始，急停和机械净空由现场人员确认。
- 代码回退不能使已经保存的 v3 档案被旧版本识别；发布说明需明确档案 schema 升级。
