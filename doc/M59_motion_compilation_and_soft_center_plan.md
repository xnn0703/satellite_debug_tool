# M59 摇摆轨迹编译与缓停回正计划

## 1. 目标

1. 固定正弦轨迹在启动前完成姿态、六缸逆运动学和控制帧编译，运行热路径只负责单调时钟调度与 UDP 发送；M60后迟到从真实发送时刻重建周期。
2. 摇摆运行期间提供单一“缓停并回正”意图：按当前连续相位逐步减小幅值，发送精确中心目标，并等待控制器反馈确认停止和回正。
3. 物理急停与软件缓停保持不同事实；软件按钮不描述为急停。

## 2. 当前事实与根因

- 有限轨迹预检已提前生成全部 `PlatformPose`，30 min / 50 ms 为 36,400 个姿态点。
- `send_trajectory_point()` 仍在每个发送周期执行六缸逆运动学和 33 字节 `0xC0` 帧编码，因此发送线程仍承担 Python 计算和对象分配。
- 当前“受控停止”只设置 `threading.Event`，其含义是“不再生成后续点”；它没有减幅段、中心命令或反馈闭环结果。
- 页面在 worker busy 时禁用“回正”，用户只能先结束摇摆，再重新发起回正。

## 3. 领域模型

### 3.1 编译轨迹

新增不可变 `CompiledTrajectory`，由 `core/motion_platform/` 独占：

- 绑定轨迹参数、运动平台配置摘要和预检摘要；
- 每个点保存计划相对时间、FRD 姿态、六缸脉冲和完整 `0xC0` 帧；
- 有限轨迹启动前全量编译；编译失败时不进入运行状态、不发送任何帧；
- 编译结果与配置或轨迹摘要不匹配时拒绝执行；
- 运行热路径不再调用逆运动学或帧编码。

无限正式工况不建立无界点表。它使用一个完整重复周期的已编译主体；不能形成有限重复周期的配置使用有界前瞻块，并由同一编译 owner 维护低水位。两种实现只向调度器暴露一个按索引读取接口。

### 3.2 缓停并回正

新增肯定式停止状态：

```text
RUNNING → FADING → CENTERING → CENTER_CONFIRMED
                         └──→ CENTER_FAILED
```

- 点击按钮只提交一次 `soft_center_requested`，重复点击幂等。
- `FADING` 从最后一个已发送点的实际相位开始，使用界面“渐出”时长；幅值包络连续下降到 0，不重置相位、不跳到另一条曲线。
- 渐出点继续使用 50 ms 资格周期，并在进入 `FADING` 时一次性编译；编译结果必须通过六缸包线检查。
- `CENTERING` 发送精确型号中心姿态，时长使用独立的回正时间合同，不复用急停或回原点。
- `CENTER_CONFIRMED` 必须由新鲜反馈证明运动停止且六缸位于目标保护范围内。
- 渐出期间出现发送故障、伺服故障或反馈失效时进入 `CENTER_FAILED`，保留当前平台事实；不得宣称已经回正。
- 物理危险仍使用平台物理急停，软件缓停不承担急停语义。

### 3.3 UI

- 运行时按钮显示“缓停并回正”，仅在轨迹 `RUNNING` 时启用。
- 点击后按钮进入“正在缓停…”且不可重复触发；轨迹参数继续锁定。
- 成功显示“缓停完成且已回正”及最大残差；失败显示明确阶段与原因。
- 普通单姿态动作继续保留独立“回正”按钮；轨迹运行时不要求先结束工程会话。

## 4. 实施顺序

1. 增加旧实现稳定复现：发送热路径仍做逆解；停止只截断且没有回正结果。
2. 建立 `CompiledTrajectory` 与配置/轨迹摘要绑定，有限轨迹改为启动前全量编译。
3. 调度器只发送已编译帧，同时保持 M58 的实际发送时间、控制空洞与完整槽位丢失证据。
4. 建立 `soft_center_requested` 单一状态机、相位连续渐出、中心反馈确认和失败收尾。
5. 接通 worker、客户/工程共享摇摆台页面与试产连续轨迹入口；删除旧“只截断”停止语义。
6. 更新翻译，执行定向、全量分段测试和真实台架抓包/MS-6222 验收。

## 5. 交付边界

- 软件测试证明编译合同、状态迁移、相位连续性、单一发送 owner 和反馈闭环语义。
- 抓包证明50 ms发送时间线、渐出点连续和最终中心命令。
- MS-6222证明实际幅值连续下降并最终稳定在标定中心附近。
- 负载下机械异响、急停距离和长期寿命仍需现场独立验收。
