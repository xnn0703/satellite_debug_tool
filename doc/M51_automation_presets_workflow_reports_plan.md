## 设计方案

### 统一保存入口

设置中的录制目录作为新批次默认根目录，自动化数据集中在以下结构。

```text
录制目录/
  自动化测试/日期/批次ID/
    batch.sqlite3
    recipe.json
    production_configuration.json
    fixtures/会话ID/原始夹具文件与清单
    devices/SN/evidence/设备SDB
    reports/SN/报告与证据包
    batch_summary.json
```

默认目录由单一保存位置解析器确定，创建时冻结到批次。主页面和完成页提供打开本批次目录、打开录制文件位置及查看报告。

保存模式显式保存为 `follow_recording` 或 `custom_root`，规则如下。

1. 新安装默认跟随 `paths.recording_dir`。录制根目录为空时，准备页提示配置保存位置，完成后继续开始流程。
2. 旧 `paths.production_dir` 为空或等于原默认 `~/SatelliteProduction` 时迁移为跟随录制目录。其他已有路径迁移为自定义根目录，设置页显示迁移后的模式、路径和来源。
3. 活动批次始终使用创建时冻结的绝对路径，设置修改影响后续批次。历史批次按原路径读取，迁移映射保留原设置值供核对。
4. 主报告和证据包位于批次目录。已有 `production_report_dir` 作为额外报告导出目的地迁移，导出失败保留主归档并提供重试。
5. 开始前验证目录可写及路径合法性。容量不足、目录失联和写入失败记录明确状态，文件收尾结果进入数据质量快照。

### 内置型号与自定义版本

- 协议产品、供电版本、测试方案分别拥有稳定身份，批次冻结三者的参数、来源、revision 和哈希。
- 主页面提供一个完整名称的型号选项，例如 AFD01C · 24 V / 5 A。选择后立即展示电压、单台限流、数量及总限流。
- 内置六个供电预置为只读目录。复制为定制生成独立模板，支持新建、导入和导出。48 V 定制版显式填写单台限流及适用测试方案。
- 表单修改在原模板上按字段更新，保留参数期望、测试扩展和时间策略。导入后显示来源、版本、供电需求、测试项目、时长及配置差异。
- 上电前使用所选供电版本与工位额定值准入，上电后依据真实身份校验协议型号和 SN。工位能力以实际设备与接线档案为依据。
- 测试时长及摇摆参数来自选定的测试方案。已验证方案可记忆为该型号版本默认项，首次配置展示明确的参数摘要。

#### 配置身份与迁移合同

内置六项使用独立、保留的稳定 ID 和 revision。自定义副本生成新 ID，并保存来源 ID 与 revision。内置更新、用户副本和已有批次快照分别管理版本。相同 ID 与 revision 内容一致时导入幂等，内容相异时显示冲突。更高 revision 的导入先显示差异，再由配置管理入口更新目录。

旧模板迁移保留原 template ID、原 revision 和完整原始 payload，生成协议产品、供电版本和测试方案的确定映射。迁移以原 schema 识别，重复执行结果一致。当前写入统一使用新 schema，历史批次读取使用原版本合同。

每个型号供电版本关联一个默认测试方案 ID/revision。优先加载该版本已配置的有效方案。首次使用、方案删除或引用失效时，准备页显示“请选择测试方案”，操作员选择已有配方或在配置管理中新建。预置供电参数以本计划的六项表为准，测试方案中的项目、时长、参数期望和运动参数均具备明确来源。

M51 新配方以逐工况 `duration_s` 表示固定窗口。旧全局时长映射到每个已启用场景，迁移记录保留原字段与原值。初始搜星属于该窗口，首次有效锁定后 SNR 判据沿用已确认规则。报告统计窗口独立保存。执行器、编辑器、进度和报告共同消费解析后的工况时长。

固件与参数校验为固定前置检查，在方案页直接说明其属性。前置检查沿用配方的明确期望。导航分析项目由方案显式启用并提供判据，适用性和结果在报告中展示。主进度节点只表示实际执行步骤，分析汇总进入收尾进度。

### 三阶段操作

1. 准备。主页面保留型号及供电版本、设备数量、测试方案、操作员。工位记忆上次选择并显示名称，详情折叠。开始测试内部完成创建批次、配置冻结、供电、身份准入及完整采集准备。
2. 运行。保留当前项目、子阶段、工况剩余时间、曲线及夹具灯。准备过程显示正在等待的设备、夹具或数据。流程节点来自本批次冻结的有效测试列表。中止按钮始终可操作，收尾状态持续可见。
3. 完成。执行 owner 自动管理停止运动、恢复采集、录制落盘、断电回读、报告归档。异常收尾保留已有安全顺序并记录各动作结果。界面提供查看报告、打开批次目录、下一批次，人工审核独立生成 V2。

正常完成的恢复确认通过异步状态推进，避免主线程等待通信结果。下一批次复用最后的型号、方案、工位和操作员，分配新批次 ID，清理上一批运行状态。

窗口支持 1280×800、1440×900 和 1920×1080 验收。主操作固定于底部，窄窗使用内容滚动。单设备占满曲线区，2 至 4 台按真实槽位排列。准备阶段显示实际等待原因，工况开始回执到达后启动该工况倒计时。

#### 生命周期与异常分支

扩展现有 `BatchCoordinator` 作为批次生命周期入口，组合 `ProductionStartPreparation`、执行器、现有中止协调器及录制 owner。页面只发意图和呈现状态。正常结束依次确认运动停止、采集恢复、设备录制落盘、供电关闭回读和夹具/电源证据收尾，随后进行质量分析及报告冻结归档。

- 恢复响应超时或运动停止失败时，沿用既有异常安全收尾，逐项记录已发送、已确认与失败原因。
- SDB 写入失败时保留可取得的原始文件和错误证据，记录证据不完整状态。
- 断电回读失败时呈现供电状态待确认，硬件资源释放条件满足后才允许下一批次。
- 报告或额外导出失败时保留测试终态与已生成主归档，提供绑定原批次的重试入口。
- 完成、中止、退出并发到达时只驱动同一收尾链。正常回执、超时和迟到回调均按 batch ID 与操作代际归属处理。

下一批次入口要求硬件控制、设备事务和录制 owner 完成释放。新批次重新解析候选设置并冻结快照。批次 ID 使用可验证的唯一分配机制，覆盖同秒创建和进程重启。旧批次异步结果只更新旧批记录。归档任务已结束且处于明确失败状态时，可在资源已释放条件下继续新批次，旧批归档重试继续使用旧批冻结上下文。

### 报告与分析包

- 每台设备的报告首页汇总型号、供电版本、SN、固件、配方版本、单台与合计电源需求、最终结果、主要异常和数据质量。
- 每个实际执行工况展示配方时长、观察起止、初次搜星耗时、搜星后最小 SNR、首次零值或负值时刻、数据缺口和结果依据。执行结果由现有领域状态提供，报告分析读取该事实。
- 全过程图标记供电、搜星、有效观察、掉线、中止等阶段，缺口分段。锁定状态采用独立状态条，SNR 保持 dB 坐标。
- 全部终态生成可读测试记录，明确通过、失败、未完成、中止。报告首页呈现该结果及原因。
- 数据质量快照统一汇总文件收尾、采集模式确认、各帧类别计数、起止与覆盖、代际、丢块及缺口。界面、报告和分析 JSON 共用此快照。
- 证据 ZIP 按设备和关联夹具会话 manifest 收集全部原始记录，保留每个会话目录、冻结配置及标定证据。SDB 保存全部收到的数据，分析导出提供带时间基准、单位和质量标记的 CSV/JSON。
- DOCX 保留修订审核机制，正文采用中文项目名称和相对时间。摘要、结果、数据质量紧凑编排，详细 JSON、完整哈希和低频技术信息归入附录或证据包。版式保留现有 A4 报告合同，调整字号、列宽、分页和字体策略。

#### 报告冻结与数据质量合同

首页分别展示执行结果、采集质量和最终报告状态。最终报告状态按中止、执行失败、执行或证据未完成、通过的顺序确定，保留每个来源事实与原因。执行通过且必需证据存在缺口时报告为未完成。执行失败且证据完整时报告为失败。执行失败同时存在缺口时报告继续显示失败，并明确标出证据缺口。

必需帧集合由已声明设备能力和方案需要的数据共同决定。SDB v2、M50 前 v3、M50 后 v3 分别按可取得的字段分析。历史版本缺少某质量字段时显示“该版本未记录”，保留可确认的帧数、文件状态和时间范围。

设备与夹具写入收尾、质量扫描、源文件清单及哈希确认后冻结报告。快照包含实际路径映射、配置及算法版本、数据质量、判定窗口和证据哈希。V1 与 V2 使用同一冻结输入，审核只增加审核事实。算法升级产生独立分析修订，记录与原报告的关联。

夹具清单冻结全部关联 session ID，各会话保留自身目录和 manifest。同名文件按会话目录区分，逐设备时间关联单独记录。缺失文件、空文件、写入未完成和哈希变化均在清单中标记对应事实。

质量扫描、CSV/JSON 导出、哈希及 ZIP 打包在后台流式完成。每次归档复用一次顺序扫描产出的统计与文件清单，图表使用有界抽样。临时产物经完整校验后原子发布，失败重试复用冻结输入。首轮性能基准采用 200～256 MiB 单设备 SDB，并覆盖 4 设备合计约 1 GiB 的完整批次及两个同名文件的夹具会话；不要求单个 SDB 达到 1 GiB。工作线程增量内存预算为 512 MiB，界面定时心跳间隔 p95 不超过 200 ms。实施前在测试日志记录运行机、输入规模与测量方法。
