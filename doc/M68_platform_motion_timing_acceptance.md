# M68 平台相关连续轨迹周期验收标准

## 自动化验收

- [x] macOS 连续轨迹周期固定为 20 ms，Windows 固定为 50 ms。
- [x] 周期只有运动领域层一个权威来源，界面和生产配置不提供可变入口。
- [x] Windows 时间线不存在全程忙等待，停止与缓停命令保持可响应。
- [x] 预编译位置帧动作时长、轨迹点数、缓停点数、指纹和生产配方使用当前平台周期。
- [x] 组合姿态包线仍使用 20 ms 安全计算分辨率。
- [x] Windows CI 不以共享 runner 的亚 25 ms P95 作为产品门槛。
- [x] Windows spawn 冷启动等待与运行期 UDP 节拍验收分离，接收线程异常形成明确断言。
- [x] 定向回归、翻译检查、全量 pytest 和 `git diff --check` 通过。

## 真实工位验收

- [ ] macOS 20 ms 现场既有基线未回归。
- [ ] Windows 连续轨迹抓包以 50 ms 为目标，无重复发送 owner、无跳点和突发追赶。
- [ ] Windows 控制器反馈连续，六轴伺服错误为 0。
- [ ] Windows 缓停渐出后由新鲜反馈确认回正。

真实工位未完成项不能由 GitHub Actions 或 loopback UDP 测试替代。
