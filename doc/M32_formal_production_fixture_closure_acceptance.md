# M32 正式试产与夹具配置收口验收标准

## A. 工作站配置

- [ ] 生产配置 v2 明确包含产品、出货包、电源、摇摆台、MS-6222 和工作站档案。
- [ ] 工作站档案缺少任一正式夹具引用时不能创建正式批次。
- [x] 摇摆台档案冻结本机 IPv4/反馈端口、控制器 IPv4/命令端口、包线和标定。
- [x] MS-6222 档案冻结 COM 口、460800 波特率、安装身份、质量门限和标定。
- [x] 电源档案冻结 TCP 端点、期望身份、额定值和稳定时间。
- [x] `PENDING-*` 标定不能进入正式工作站。
- [x] 批次快照保存所有 revision、SHA-256 和组合配置 SHA。

## B. 配置界面

- [ ] 生产配置管理提供产品、出货包、电源、摇摆台、MS-6222 和工作站页面。
- [ ] 电源、摇摆台和 MS-6222 均能在配置页执行无危险的连接测试。
- [x] MS-6222 可以从当前串口列表选择 COM，串口不存在时显示“需要绑定”。
- [x] 自动化页面选择工作站后显示三个夹具的实际端点和标定信息。
- [x] 批次创建后修改工作站配置不改变该批次冻结快照。

## C. 导入导出与迁移

- [x] 配置包 v2 自包含全部被引用档案和坐标标定。
- [ ] 导入在全部 schema、引用、revision 和哈希通过后原子提交。
- [x] 相同 ID/revision 但哈希不同明确冲突且不部分覆盖。
- [ ] v1 配置和 `production.ms6222_port` 只迁移一次，业务运行只读新 profile。
- [ ] 跨工作站导入后缺失 COM 进入“需要绑定”，不会猜测串口。

## D. 单一所有权

- [ ] `FixtureRuntime` 是摇摆台 worker、MS 串口 worker和夹具状态 Store 的唯一 owner。（状态 Store 已统一，物理 worker 尚待迁入）
- [ ] Production、Customer 和 Engineering 只通过 Runtime 租约控制夹具。
- [ ] 页面关闭不停止正式批次，应用退出执行受控停止和证据收尾。
- [ ] 页面级重复 worker、连接参数和旁路状态源全部删除。
- [ ] 电源、摇摆台、MS 或设备事务之间的 owner 冲突有明确状态。

## E. 正式状态语义

- [x] 夹具仅显示未配置、需要绑定、已配置、连接中、已连接、就绪、运行或故障。
- [ ] 测试项目仅显示待执行、准备中、收敛中、采集中、分析中和终态。
- [x] “待验证”“工程验证用途”和工程预览文案按计划条件删除。
- [ ] 发送成功、设备接受、回读应用和物理结果继续分别呈现。
- [ ] 工作站夹具自检使用版本化门限并产生明确通过/失败证据。

## F. M31 出货整备

- [ ] 正式批次引用不可变 ProvisioningBundle。
- [ ] 固件已经一致时不 OTA，不一致时完成签名 OTA和同一身份返回确认。
- [ ] 参数已经一致时不写入，只写受管差异并逐项读回。
- [ ] SN、MAC、硬件 UID和设备独有校准不被通用基线覆盖。
- [ ] 全部设备达到 `ready_for_test` 后才允许进入工况。
- [ ] 最终出货 IP在测试证据冻结后逐台隔离写入和确认。

## G. 正式自动工况

- [ ] 自动流程完成夹具预检、设备整备、静态、锁定后摇摆、摇摆中上电、回中、断电和归档。
- [ ] 每个步骤只依据明确硬件回执和分析结果推进。
- [ ] 共享夹具动作只执行并记录一次，每台设备独立分析和判定。
- [ ] 单台设备 FAIL 不改变其他设备；共享夹具故障使相关步骤 `INCOMPLETE`。
- [ ] 中止、断网、掉电、参考失效和设备重启异常均执行安全收尾。
- [ ] 真实车辆工况保留人工安全门禁。

## H. 报告与证据

- [ ] 报告记录电源、摇摆台、MS-6222 的型号、端点、档案 revision和 SHA。
- [ ] 每个工况包含 SNR、锁定、目标/实测姿态、误差、功耗和阶段结论。
- [ ] evidence.zip 包含整备、夹具、工况和最终 IP证据。
- [ ] manifest 校验全部关键文件 SHA-256。
- [ ] PASS/FAIL 生成 V1；INCOMPLETE/ABORTED 不生成 Word；V2审核规则保持有效。

## I. 自动化回归

- [ ] 配置解析、迁移、依赖缺失、哈希冲突和跨机 COM 绑定有测试。
- [ ] 三夹具连接、租约冲突、页面生命周期和应用退出有测试。
- [ ] M31 固件、参数、endpoint 迁移和最终 IP状态机有测试。
- [ ] 正常、单 DUT失败、共享夹具失败、断网、掉电、参考失效和中止有流程测试。
- [ ] 翻译检查、`compileall`、`git diff --check` 和全量 pytest 通过。

## J. 真机验收

- [ ] 目标 Windows 工位选择实际电源 IP、摇摆台端点和 MS COM 后可保存并重启恢复。
- [ ] 三个夹具通过工作站自检并生成完整证据。
- [ ] 一台 DUT 完成出货整备、三工况、最终 IP和 V1报告。
- [ ] 两台 DUT 完成共享工况、独立结论、证据切片和相同出货 IP逐台确认。
- [ ] 夹具或 DUT异常时平台安全停止、电源关闭且结果可复核。
- [ ] Windows 打包版无开发环境运行通过，正式页面不再显示工程预览。
