# v1.6.0 Windows 发布说明

## 主要更新

- 新增三工作区 TCP Shell + YMODEM 弹窗：客户侧栏、工程顶栏与试产导航的“TCP Shell…”入口复用同一个弹窗实例，跨工作区切换存活。
- TCP Shell 为哑终端交互：按键直接在终端区输入并发送原始字节，等宽字体、ANSI 颜色、退格与行首覆盖渲染，行编辑与历史由设备端 Letter Shell 完成（默认端口 `1235`）。
- 内置严格 YMODEM Batch Sender：`rb` → `C` 握手 → 1024 字节 STX 块 → EOT 两阶段 → 空文件名批次结束；文件名原样传递（`<target>_app_X.Y.Z_beta.bin` → 设备 DOWNLOAD 区、`app_factory.bin` → FACTORY 区）；显示进度、速度、重传与设备端路由提示。
- YMODEM 与客户 `.sfpkg` OTA、参数写入、试产批次共用设备事务互斥；手填未管理目标允许直传并在证据中记录。
- TCP Shell 会话证据保存到 `tcp_shell_sessions/`：TX/RX 原始字节、YMODEM 逐块记录、事件、SHA-256 与原子 manifest。
- AFD01D 完成独立产品身份接入：Debug hw_type、Product Identity、加密 OTA 包与试产 recipe 精确准入，内置 `afd01d.stl` / `afd01c.stl` 3D 模型。
- 客户固件包版本策略：新生成 `.sfpkg` 默认允许升级、同版本重装和降级；上位机仍严格执行经 AES-256-GCM 认证的 manifest 策略。
- DEBUG OTA 旧固件响应合同迁移：低于 `0.0.131_beta` 的已认证客户包按有界旧合同（`OK` / `dup OK` / `OK, rebooting`）推进；`0.0.131_beta` 及以后只接受带阶段和序号的正式响应。

## 真机验证边界

- YMODEM 传输完成只证明字节已被设备接收校验；升级生效由设备重启后握手回读独立呈现，上位机不自动判定成功。
- 真机已完成：`afd01c_app_0.0.132_beta.bin` 784392 字节传输（158 KiB/s、零拒包），设备日志证明候选写入 raw download 区，Boot 安装链与版本回读一致。
- 待现场复核：跨产品文件名被设备拒绝的证据记录、YMODEM 持锁期间客户 OTA 的互斥拒绝、AFD01D 真机身份回读与 `.sfpkg` 升级闭环、`0.0.130_beta → 修复版本` 引导升级全链。
- TCP Shell/YMODEM 是工程工具路径；`.sfpkg` 仍是客户升级路径。
